# Fixed-camera 2D path control: landscape and first experiment

**Updated:** 2026-10-02  
**Decision:** begin with one visible object following an image-plane path under a fixed camera. This is the first contained benchmark, not a claim about 3D pose, contact, or physics.  
**Evidence status:** source audit updated; scorer arithmetic, blinded-package mechanics, and paired Kubric left/right truth renders now pass on CPU. Independent double-label reliability is pending. No DiTraj generation or feedback-policy result has been run in this task.

## 1. Research question

Can a video diffusion model make one object follow a commanded 2D path, and can an internal state-feedback intervention correct the remaining path error without hiding, shrinking, duplicating, or visually corrupting the object or moving the background?

The first fixture is the red ball in the existing Wan2.1-T2V-1.3B M0 clip. A sphere tests image-plane position only. Apparent extent, identity, visibility, and background stability are failure guards. A later rigid-pose experiment needs an asymmetric object and simulator/rendered ground truth.

## 2. Method landscape and novelty boundary

| Family / source | Control signal and intervention | Fit to first box | What it means for our contribution |
|---|---|---|---|

Training-free; has Wan2.1-1.3B code. | **Closest runnable baseline** to current T2V checkpoint and box-path setup. | Reproduction alone is not LatentGate. | **Motion-Zero** ([paper](https://arxiv.org/abs/2401.10150), [project](https://vpx-ecnu.github.io/MotionZero-website/)) | Zero-shot box trajectories; initial-noise prior, attention constraints, temporal-attention shift. | Relevant training-free method precedent; different implementation/model stack. | Box-trajectory guidance and iterative denoising modification are established ideas. |
| **FreeTraj** ([paper](https://arxiv.org/abs/2406.16863), [repo](https://github.com/arthur-qiu/FreeTraj)) | Initial-noise perturbation and attention control; VideoCrafter2. | Useful alternative mechanism, but not a Wan baseline and has research/noncommercial restrictions in the checked repo. | Do not claim novelty for general test-time trajectory injection. |

| **Tora** ([paper](https://arxiv.org/abs/2407.21705), [official repo](https://github.com/alibaba/Tora)) | Learned trajectory patches via a 3D VAE and DiT fusion; public CogVideoX path. | Architectural/training precedent, not the least-cost Wan1.3B experiment. | Learned trajectory encoders are not new; test-time adaptation is a better first research axis. |
| **MagicMotion / MagicData / MagicBench** ([paper](https://arxiv.org/abs/2503.16421), [repo](https://github.com/quanhaol/MagicMotion)) | I2V with dense masks, boxes, or sparse boxes; dataset and benchmark; shape-preservation signals. | Strong measurement and shape-guardrail reference; I2V path and 23-GB inference requirement reported by the authors, so not the T4 pilot model. | Shape-preservation heads/losses and multimodal path formats are already explored. Use its benchmark design as a comparator, not as proof our small T2V result generalizes. |
| **ATI** ([paper](https://arxiv.org/abs/2505.22944), [repo](https://github.com/bytedance/ATI)) | Learned trajectory injection with full DiT fine-tuning at large GPU scale. | Not a free-T4 route. | A trained architecture can improve control, but its training recipe is not our feasible first method. |
| **FlexTraj** ([paper](https://arxiv.org/abs/2510.08527), [repo](https://github.com/bestzzhang/FlexTraj_code)) | Point paths with segmentation and track IDs; sequence concatenation and annealed supervision. | High-priority audit, but not currently a plug-in 1.3B baseline: while setup instructions request Wan2.1-T2V-1.3B, checked `WAN/infer_control.py` hardcodes Wan2.2-TI2V-5B shards, T5, VAE, input image, and a 50-step I2V call. The repo/HF checkpoint card has no clear model license and no VRAM requirement is published. | Identity-coded trajectory conditioning is a collision. Resolve the code/instruction mismatch and model/license/runtime uncertainty before using it as a baseline. |
| **Wan-Move / MoveBench** ([paper](https://arxiv.org/abs/2512.08765), [official repo/data](https://github.com/ali-vilab/Wan-Move)) | Dense point tracks; propagates first-frame features along tracks into latent conditions; Wan-I2V-14B. | Best modern Wan-family data/annotation reference, but its 14B I2V model is far beyond the tiny T4 baseline. | Feature propagation along the desired track is already a strong open-loop latent guidance mechanism. MoveBench provides useful masks/points and evaluation examples. |
| **MotionStream** ([paper](https://arxiv.org/abs/2511.01266), [official repo](https://github.com/alex4727/motionstream)) | Adds track embeddings to Wan I2V teacher variants, including Wan2.1-1.3B, then distills a causal streaming student with self-forcing/DMD and attention sinks. It reports user-controlled tracks/camera trajectories and text-motion guidance. | Direct model-family collision, but I2V (not our T2V starting point), training/distillation work, H100 speed claims, and the repo says code is under company internal review. No runnable code or checkpoint surfaced. The paper also notes strict track guidance can make motions overly rigid/planar, supporting independent quality/shape guards. | Do not frame track-conditioned Wan1.3B or trajectory following as new. Distinguish autonomous internal output-state residual feedback from external user-edited streaming tracks. |
| **4DStreamCtrl** ([paper](https://arxiv.org/abs/2608.25479), [project](https://4dstreamctrl.github.io/)) | Combines 3D point tracks, depth, and camera motion; Wan2.2-TI2V-5B teacher and four-step causal student. | Later-stage 4D/interactive reference; reported large-scale training resources, no model code/checkpoint found in its project repo. Its paper compares against MotionStream, but these are distinct methods. | Online user revisions are different from autonomously measured denoising residuals. Do not claim generic online or interactive path control as new. |
| **TrajLoc** ([paper](https://arxiv.org/html/2607.00861v1), [official repo](https://github.com/Sela-Omer/traj-loc)) | Replaces object-token cross-attention weights with per-frame Gaussian target heatmaps; reports multi-object identity and trajectory control. | Paper evaluates Wan2.1-14B/CogVideoX-5B, not our 1.3B T2V. The paper-linked repository exists, but its README says “Code coming soon”; no runnable implementation/checkpoint surfaced. | Do not claim novelty for target-centered attention heatmaps or per-object trajectory tokens. It is open-loop target conditioning, not measured state-error feedback. |
| **WorldForge** ([paper](https://arxiv.org/abs/2509.15130), [official repo](https://github.com/Westlake-AGI-Lab/WorldForge)) | Geometry-guided latent self-correction/predictor-corrector and motion gating; Wan2.1-I2V-14B in the large setup. | Good corrective-sampling prior; heavy and camera/view-trajectory oriented. | Generic “self-correction during denoising” is not novel. Our question must be object-specific signed path-error feedback with independent evaluation. |
| **VGGRPO / Geometry Forcing** ([VGGRPO](https://arxiv.org/abs/2603.26599), [Geometry Forcing](https://arxiv.org/abs/2507.07982)) | Latent geometry reward/gradient or intermediate-feature alignment to geometry teachers. | Adjacent policy/representation references, not direct 2D path methods. | Generic latent reward gradients and geometry-feature alignment are prior art. They may later supply an observer/teacher, but a moving-object target reward is needed. |

### Current novelty assessment

The defensible research hypothesis is narrow: **estimate the object’s current projected state from an intermediate clean-video estimate, compare it with the commanded per-frame path, and use signed state error plus confidence to adapt the next denoising control update.** Compare that policy with (a) no trajectory control, (b) fixed open-loop DiTraj, and (c) a fixed-strength/schedule intervention matched for compute. Include a zeroed/shuffled-state policy ablation. This is a hypothesis, not an established novelty claim; the literature audit should continue before publication-level claims.

## 3. Evaluation landscape and choice

| Resource | What it supplies | Use here / limitation |
|---|---|---|
| **DiTraj evaluator** ([paper](https://arxiv.org/abs/2509.21839)) | OWL-ViT boxes; coverage, box IoU, center distance, AP50. | Keep as secondary method-comparable metrics. A framewise detector is not identity ground truth and can share prompt bias. |
| **MoveBench** ([Wan-Move repo](https://github.com/ali-vilab/Wan-Move)) | Curated motion-control videos with trajectory and first-frame object annotations. | Useful for external stress testing and annotation conventions; its base method is large I2V and its conditions differ from our one-object T2V fixture. |
| **MagicBench** ([MagicMotion repo](https://github.com/quanhaol/MagicMotion)) | Motion-control evaluation stratified by object count/control type, with video and trajectory metrics. | Good future comparison; task interface/model differs, so published scores are not numerically comparable to DiTraj. |
| **MC-Bench** ([MotionPro repo](https://github.com/HiDream-ai/MotionPro)) | User-drawn path/mask conditions and motion-evaluation measures based on image/video features and tracking. | Useful broad robustness battery; no paired target video means generated-object tracks are still estimated, not ground truth. |
| **TAP-Vid / TAPNext++** ([benchmark and official tracker](https://github.com/google-deepmind/tapnet)) | Point tracks with visibility; real and synthetic benchmark protocols. | Use TAPNext++/TAPIR as an independent motion cross-check, not as the primary box/mask label. A tracker point on a rolling sphere is a surface point and can move relative to the sphere's projected center. Pin the checkpoint/license provenance; the current TAPNet README states Apache-2.0 for checkpoints. |
| **FlexBench** ([dataset page](https://huggingface.co/datasets/bestzzhang/FlexBench)) | 40 examples split across dense, spatial-sparse, temporal-sparse, and unaligned trajectory control. | Small external path-format stress set; protocol differs from our fixed-camera T2V task, so it cannot replace matched counterfactuals. |
| **SAM2.1** ([official repo](https://github.com/facebookresearch/sam2)) | Prompted video masks and propagation; practical manual-label proposal. | Use to propose masks, then human-correct. Propagation can drift; never treat it as exact labels. |
| **Kubric / MOVi** ([official repo](https://github.com/google-research/kubric)) | Scripted scenes with exact masks, depth, camera, object pose, and point trajectories. | Best controlled fixture to validate metrics and tracking failure cases before model clips. Synthetic ground truth does not label generated M0 outputs. |
| **Wan-Move annotations** ([repo](https://github.com/ali-vilab/Wan-Move)) | Real motion-control annotation examples. | Later external validation; does not replace our own fixed-camera paired tests. |

### M0 annotation contract

1. Freeze the target path and evaluator before looking at treatment outputs. Randomize clip IDs; the annotator records per-frame visibility, instance count, identity consistency, center, and bounding box (mask where unambiguous) without arm labels or target path. Add structured identity/duplicate fields to the current annotation CSV before using it as a benchmark record; free-text notes alone are ambiguous. The proposed paired-path schema is in [`path_counterfactual_spec_v1.json`](path_counterfactual_spec_v1.json).
2. Use manual labels as the small pilot’s adjudicated primary score. A detector, SAM propagation, red threshold, and point tracker can propose/cross-check labels; none is the sole source of truth. Double-label a random subset to estimate annotation noise if feasible.
3. Primary metrics: normalized center ADE and FDE (distance divided by image diagonal), full-frame coverage, target-box IoU, and signed endpoint displacement in the commanded direction. Missing detections remain in coverage and receive the predeclared maximum normalized error; do not drop failures from ADE. Compute monotonicity only over adjacent frame pairs where both frames are visible, and report the valid-pair denominator—do not bridge a missing interval by compacting valid detections.
4. Guardrails: identity/duplicate count, apparent box width/height and mask-area variation, background-point displacement/camera stability, and blinded visual-quality preference. Report each separately; never trade disappearance or camera motion for a better path score.
5. Keep evaluator inputs separate from policy inputs. The red-pixel threshold is a quick secondary diagnostic only: visual mask overlays show threshold holes around specular highlights, and it remains sensitive to hue, reflections, and lighting. Background point motion is only a camera-stability proxy; the smooth white tabletop has few reliable landmarks, so choose visible static edges/points and do not treat low optical flow as proof of a fixed camera.

## 4. Causal pilot protocol

### Prompt and path isolation

Use a direction-neutral scene prompt: “A single bright red ball on a plain matte gray tabletop; locked-off camera, even lighting, no other moving objects.” Do not put “left to right,” “right to left,” or a similar direction in text. Use the same prompt, negative prompt, sampler, initial latent tensor, seed, model checkpoint, frame count, and decode path across arms.

The current local paired-path notebook resolves the earlier one-way-path flaw: its neutral prompt is shared across paths, both paths begin at x=.50 with identical box size/y center, and their endpoints are mirrored at x=.70 and x=.30 with common initial noise. This makes direction the intervention variable in the saved local source. The Kaggle draft still does not contain this runner, so no direction-counterfactual experiment has run yet.

### Ordered gates

| Gate | Run | Pass evidence |
|---|---|---|
| 0 — scorer check | Render a tiny Kubric clip with known point/box/mask truth; verify normalization, missing-frame penalty, left/right sign, and blinded annotation package. Current: paired 17-frame directions and mask scoring pass; independent double-label reliability remains. | Metrics recover known paths and flag missing/duplicate frames. |
| 1 — environment smoke | In an already verified free GPU session, run one no-control step and a short full-control DiTraj smoke at 17 frames; record memory, time, output shape, and all masks. | Correct model load, 17 decoded frames, no inactive control path or indexing error. |
| 2 — matched method smoke | Base / foreground-background path control / full DiTraj with one direction and shared initial latents. | All arms complete and the logged path-to-token mapping is correct; one clip per arm is feasibility only. |
| 3 — direction counterfactual | Base and full DiTraj under both mirrored paths, matched per seed; add the intermediate SG arm if compute allows. | Correct signed endpoint response and lower independent path error for the appropriate target; control/noise/prompt matching verified. |
| 4 — seed confirmation | If the pilot is scoreable, run at least five matched seeds and retain all failures. Add a piecewise stop/turn path only after horizontal movement passes. | Paired changes with intervals; visibility and scene-quality guardrails remain acceptable. |
| 5 — state observer and gate | Preserve spatial transformer features and/or decode selected predicted-clean states; test held-out-seed state-to-center observability, then compare fixed DiTraj with residual/confidence-conditioned control. | Observer beats a constant/prompt-only baseline, calibrates confidence, and shuffled/zeroed state removes the gain. |

At the current clip scale, evaluate all RGB output frames 0–16. The saved 17-frame Wan run has five latent-time positions; VAE temporal-compression metadata gives them nominal RGB-frame anchors 0, 4, 8, 12, and 16. These anchors are stride references, not disjoint frame groups or measured receptive fields. The DiTraj bbox map lives on the post-patch 30×52 spatial grid, not the raw 60×104 VAE latent grid. Record the RGB frame index, latent-time index, and denoising step separately in each run manifest.

### Candidate first feedback law

At the predeclared zero-based step 4, capture the exact scheduler-converted predicted-clean state, estimate the object center/confidence, and compute `e[t] = target_center[t] - estimated_center[t]`. The first candidate applies a bounded residual to later foreground cross-attention boxes; it leaves DiTraj's hard first-three-step RoPE geometry unchanged. The existing M0 previews show a measurable red-ball proxy at steps 4/14/24, but step 4's bbox agreement is weaker than step 14, so observer validation against blinded labels is required and no gain is claimed. Start with one decode/update after step 4, then consider step 14 only if the one-read arm passes. Compare against fixed DiTraj, compute-matched decode/no-op, shuffled-state, and sign-reversed-state arms. This remains a proposal until the pinned T4 path measures scheduler capture, VAE memory/latency, and generated-sample response.

## 5. Resource and implementation constraints

- Current M0 baseline: Wan2.1 T2V 1.3B, 832×480, 17 frames, 30 steps on a T4; one red-threshold proxy only. That does not establish DiTraj compatibility, feedback feasibility, or a policy gain.
- Current model-state summaries are spatially pooled `[1,5,1536]` mean/std features and cannot localize an object. Future capture must preserve a spatial grid or use decoded predicted-clean estimates.
- The pinned DiTraj path assumes BF16 and full-CUDA loading; a T4 route needs FP16 and measured offload. UMT5 prompt encoding and the dense repeated-token attention mask are concrete runtime risks. A shorter partial-step smoke should precede a full matched run; if the implementation changes the paper schedule, version and report it.
- No GPU inference has run for DiTraj in this task. A fresh read-only check of the private [Kaggle draft](https://www.kaggle.com/code/bvyashwantkumar/ditraj-wan-1-3b-pilot-research/edit) found Draft saved, session off, T4×2 selected, and only four cells: setup, blank, and duplicate T4 preflights. The runner, bounded smoke, and result-review cells are absent from the saved draft. No quota has been consumed for DiTraj. Do not treat selected hardware as a started experiment; stage and review the runner before any GPU session.
- Repositories, code, weights, and datasets have separate terms. DiTraj states CC BY-NC 4.0; FlexTraj's root license was not located; follow each source’s current terms before reuse. “Publicly downloadable” does not mean unrestricted reuse.
- The local red-threshold evaluator is a screening tool; its compact-valid-sequence monotonicity can bridge missing frames. Use adjacent-pair monotonicity with an explicit denominator for the manual benchmark. DiTraj's paper-faithful runner also preserves its inclusive-corner/exclusive-slice off-by-one in the RoPE remap; the separate half-open primitive is a distinct algorithm version and must be reported as such if used.

## 6. Stop rules and claims

- Stop the trajectory branch if independent labels cannot track one object, path direction is leaked through prompt/starting state, the pipeline control mask is inactive, or matched noise/settings cannot be reproduced.
- Do not call one-sample results improvements. One direction with a direction-specific prompt is a runtime smoke, not a causal control result.
- Do not claim a native policy gain if a fixed schedule, extra denoiser calls, or an unconditioned sampling change accounts for it.
- Do not claim 3D geometry, rigid orientation, contact, or physics from the red sphere and image-plane boxes. Advance to an asymmetric CAD object and Kubric/robot simulator only after this first component passes.
