## 2. Receive and preserve genuine returns

1. The v5 owner handoff asks raters to return a plain CSV. The intake scanner also recognizes a `.zip` envelope only when it has exactly one `.csv` member of at most 10,000,000 bytes and no member whose basename contains `UNBLIND` or `PRIVATE_KEY`. This is intake-scanner acceptance, not direct scorer support: the agreement/truth scorers take CSV paths, so a ZIP needs a verified extracted working CSV before scoring.
2. Accept a return only from its assigned rater through the coordinator's controlled channel. Do not create a receipt for a blank template, QA/synthetic export, placeholder, or file not genuinely returned by that rater. Before parsing or extracting anything, copy the exact received envelope bytes (the plain CSV or the whole ZIP) to `/Users/yash/Library/Application Support/LatentGate/Gate1/originals/` while computing SHA-256, and record `received_format` as `csv` or `zip`. Create private files as owner-only regular files (mode `0600`); create no symlinks. Treat the preserved envelope as immutable. Limit plain CSV envelopes to 10,000,000 bytes and ZIP envelopes to 12,000,000 bytes during the bounded copy; reject oversized envelopes without parsing. Keep the original filename only in the coordinator-only custody record. Name the opaque original envelope `<receipt_id>.envelope`; name the one CSV staging file `<receipt_id>.csv`; name the receipt sidecar `<receipt_id>.json`. Stage any scan/scoring copy under that opaque receipt-based name because reports can record resolved paths; never use a person's name in a staged filename.
3. For a plain CSV, the scored CSV bytes are the received envelope, so `scored_csv_sha256` equals `received_file_sha256`. For a ZIP, prefer requesting the plain CSV unless there is a concrete need for the ZIP. After recording the envelope hash and format, accept a ZIP only if it has exactly one archive member total: one regular `.csv` entry, at most 10,000,000 uncompressed bytes. Reject envelopes over 12,000,000 bytes, extra entries, directory entries, duplicate names, path-like member names, Unix symlink/special-file entries, the existing `UNBLIND`/`PRIVATE_KEY` blacklist, or any entry with the ZIP encrypted flag; never request a password. These are coordinator intake limits; the current scanner does not enforce all of them.
4. Do not call `extractall()`, `extract()`, or create a destination from the member filename. Select the single entry as a `ZipInfo` object from `infolist()` and stream it in bounded chunks to a securely created opaque temporary filename in `/Users/yash/Library/Application Support/LatentGate/Gate1/staging/`. Enforce an actual emitted-byte limit of 10,000,000 while streaming, compute `scored_csv_sha256` over those bytes, and require the final byte count to match `ZipInfo.file_size`; read to EOF so the ZIP reader can perform CRC checking. If any size, CRC, encryption, path, duplicate, or type check fails, delete the temporary copy and stop before scoring. Do not pass the ZIP path itself to the agreement/truth scorer.
5. Only after a genuine return arrives, create one separate `gate1_submission_receipt_v1` JSON sidecar under `/Users/yash/Library/Application Support/LatentGate/Gate1/receipts/`. Set `schema` to `gate1_submission_receipt_v1`; include `receipt_id`, `packet_id` (the manifest-relative archive path), `packet_sha256` (the assigned packet ZIP SHA-256), `rater_token`, `received_utc`, `received_format`, `received_file_sha256` over the exact received envelope bytes, `independence_attestation_version` (`gate1_independence_v1`), `independence_attestation` (the exact statement “I completed this packet independently, did not inspect another submission, and did not coordinate labels.”), and `scored_csv_sha256`. For a ZIP only, also record `csv_member_ordinal` as `1`, not its internal filename; for a plain CSV, omit that field and require `scored_csv_sha256` to equal the envelope hash. Restrict `receipt_id` to 16–64 ASCII letters, digits, `_`, or `-`; use it as the basename of the `.json`, `.envelope`, and `.csv` files described above. Retain any original or member filenames only in the private custody record, not the receipt or scan-visible path. Do not put names, email addresses, labels, blind aliases, direction mappings, or the token-to-person roster in the sidecar.
6. Keep receipt sidecars in `receipts/`, the token-to-person roster in `private_roster/`, and all scan/scoring copies and annotation-derived reports in `staging/`. No rater token is inserted into the v5 schema or packet.
