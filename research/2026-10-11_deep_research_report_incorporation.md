## Findings to carry into the local plan

The report keeps three evidence classes separate:

1. **Observer mechanics:** low error is reported on a small synthetic Kubric calibration set. This does not establish transfer to generated Wan videos or reliable identity tracking.
2. **Actuator implementation:** an opt-in UniPC predicted-clean capture path, DiTraj adapter, and smoke runner are reported implemented. The CPU scheduler equality check is plumbing evidence only; a GPU smoke has not passed.
3. **Policy efficacy:** no DiTraj GPU feedback video, path improvement, or feedback gain has been measured.

The source audit reports these implementation constraints for the pinned [DiTraj repository](https://github.com/xduzhangjiayu/DiTraj/tree/6fa8e613c9e7c40ec2db456ab2ba34367a076886) and [Diffusers UniPC scheduler v0.33.1](https://github.com/huggingface/diffusers/blob/v0.33.1/src/diffusers/schedulers/scheduling_unipc_multistep.py):

- DiTraj builds its cross-attention mask before denoising; its callback runs after `scheduler.step`. A callback-only bbox edit therefore cannot update the next transformer call. A working loop needs persistent active-box state and must rebuild the next mask before transformer execution, while logging rasterized masks and preserving the selected early RoPE geometry.
- For the cited flow-prediction UniPC configuration, the report identifies predicted-clean conversion as `x0_hat = x_t - sigma_t * v_theta(x_t,t)`. The actual GPU capture still needs verification under the pinned model, scheduler, dtype, and callback timing.
- At 832×480, the spatial control grid is 52×30; a 17-frame adaptation uses five temporal box slices at frame anchors 0, 4, 8, 12, and 16. Upstream examples default to 81 frames, so the short route is an adaptation, not an established upstream runtime result.
- Upstream `run.py` defaults `fixRope_step` to 5; the local protocol's first-three-step hold is a separate choice that must be explicit in the run configuration.
- The report records DiTraj code as CC BY-NC 4.0 and the Wan Diffusers checkpoint as Apache 2.0. Keep the adaptation research-only under the current code-license evidence.

The wider comparison set named in the report includes DiTraj, FreeTraj, Motion-Zero, Tora, SG-I2V, TrajLoc, Wan-Move, MagicMotion, FlexTraj, WorldForge, MotionStream, 4DStreamCtrl, Geometry Forcing, VGGRPO, PSIVG, and Track4Gen. The report warns that generic latent correction, attention-map steering, training-free trajectory constraints, and simulator-in-the-loop video control already have prior art. Any novelty claim must be narrower and causal: a fresh estimate of generated-state error must improve a later action beyond matched fixed, no-op, shuffled-state, and sign-reversed controls.

The report's artifact and resource screen narrows practical choices. DiTraj is the closest released Wan T2V 1.3B code path but carries CC BY-NC 4.0 terms. FreeTraj is another training-free trajectory-control precedent with a noncommercial/research disclaimer. SG-I2V provides MIT-licensed latent optimization code, but its published SVD test uses a 48 GB A6000. The report places Tora's released CogVideoX-5B variant around 30 GiB on an A100, Wan-Move's low-memory single-GPU path at 40 GB, and MagicMotion below 24 GB on an RTX 4090; these are not T4 feasibility claims. MagicMotion and FlexTraj have released benchmarks/data or checkpoints that make them useful I2V comparison points, while the report could not establish a runnable release for Motion-Zero or TrajLoc. MotionStream's code was still under review and 4DStreamCtrl's code/paper were described as forthcoming. WorldForge is a public Apache-2.0 training-free 3D/4D comparator. These alternatives sharpen novelty and resource boundaries but do not replace the current small T2V path experiment.

The report's global comparison includes work from multiple regions. It specifically identifies Motion-Zero (East China Normal University), Tora (Alibaba), MagicMotion (Fudan University and Microsoft Research Asia), FlexTraj (City University of Hong Kong / University of Hong Kong / Microsoft), and WorldForge (Westlake University). Their inclusion prevents treating the trajectory-control landscape as only a North American or European one; this is a scoped literature snapshot, not a claim of exhaustive coverage.
