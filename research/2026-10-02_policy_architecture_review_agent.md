# LatentGate P4 policy architecture review

**Date:** 2026-10-02  
**Scope:** architecture and feasibility audit for fixed-camera, single-object 2D path adherence on the local Wan2.1-T2V-1.3B / pinned DiTraj route.  
**Execution:** source and paper review only. No implementation files were changed; no inference or tests were run.

## Recommendation

The smallest credible causal experiment is a **single-read, bounded state-feedback controller over DiTraj's existing foreground cross-attention boxes**. After denoising step 4, use the current guided UniPC predicted-clean estimate $x_{0|t}$ from that sample, decode it once, estimate the object's center in all 17 frames, and calculate a bounded signed path residual at the five Wan latent-time positions. Re-rasterize only the later foreground/background cross-attention mask and continue the same denoising trajectory. Leave DiTraj's fixed first-three-step RoPE intervention unchanged.

This is the most practical first *causal control* because the action is explicitly a function of the generated sample's measured state, the source patch has a precise post-scheduler insertion point, and it avoids backward propagation through Wan. It is a single closed-loop update, not yet a learned policy or a native all-latent observer. The research contribution is not established unless held-out state feedback improves against full DiTraj and matched fixed-action controls. Existing work already covers trajectory-conditioned latent optimization and predicted-clean gradient guidance, so any novelty claim must stay narrow.

Do not start with LoRA/GRPO, a trainable geometry model, or end-to-end reward gradients. First show that DiTraj works in the matched fixture, validate that the state observer tracks independent labels, and show that changing the control mask changes the resulting path in the intended direction. If that works, the most meaningful route toward a native latent gate is to distill a spatial latent-state estimator into a small head and reuse the same bounded control law.

## Local route and causal insertion point

At the 832×480, 17-frame fixture, Wan's causal VAE maps the video to 5 latent-time slots. The latent is `[1,16,5,60,104]`; Wan's `(1,2,2)` patch projects it to 5×30×52 = 7,800 video tokens. DiTraj holds a `[5,1,30,52]` bounding-box mask, uses foreground/background prompt tokens with a cross-attention mask, and applies its separate spatial RoPE adjustment in the first `fixRope_step` calls.

The relevant pinned flow is:

```text
z_i + prompt
  → DiTraj Wan transformer (positive and CFG-unconditional calls)
  → CFG-combined velocity
  → UniPC scheduler conversion / sample update
  → at i = 4: save converted x0_hat, VAE decode, estimate five object centers
  → bounded target-relative box update
  → rebuild cross-attention mask
  → continue steps i = 5 onward with the updated mask
```

At the feedback hook, the observer consumes the scheduler's exact `convert_model_output` result. For this pinned configuration (`prediction_type="flow_prediction"`, `predict_x0=True`), Diffusers computes `x0_hat = sample - sigma_i * guided_velocity`. The adapter arms capture immediately before `scheduler.step`, verifies UniPC's `step_index`, clones the result, and consumes it after that step. This is the correct pre-update estimate for the current denoising state, and it remains causal when it controls only subsequent denoising calls. See [the adapter](ditraj_feedback_adapter.py#L239) and pinned [UniPC source](https://github.com/huggingface/diffusers/blob/v0.33.1/src/diffusers/schedulers/scheduling_unipc_multistep.py).

DiTraj's pipeline constructs `cross_attention_mask` once before the loop, rebuilds a fresh attention dictionary each iteration, and invokes its callback after the scheduler update. The local adapter retains `bbox_mask` in pipeline scope, replaces it after step 4, and reconstructs the mask used in subsequent eligible transformer calls. This is the right seam for a bounded controller; the custom [adapter patch](ditraj_feedback_adapter.py#L48) and [runner](run_ditraj_feedback_pilot.py#L124) preserve the pinned implementation as the control base.

The update is intentionally distinct from a direct pixel translation: it changes which video tokens can attend to foreground versus background text. The object may not move monotonically with the mask shift. Therefore the action's direction and magnitude must be experimentally measured, not inferred from source semantics. The current controller computes `delta = clip(gain * (target_center - observed_center), ±1 token)` for trusted unlocked boxes, preserves continuous box extent, and locks the first box. Its red-threshold agreement score is a heuristic rather than a calibrated confidence probability. See [controller](box_residual_feedback.py#L17) and [observer/action logic](ditraj_feedback_adapter.py#L316).

The existing 8-step smoke would give the update only steps 5–7; it tests plumbing, not useful efficacy. The 30-step pilot with `mask_step=18` gives the update steps 5–17 while the base DiTraj cross-attention intervention remains active. The RoPE and repeated-token mask are computed from the original boxes, but the feedback action occurs after the three RoPE-modified calls; so they do not need to be refreshed for this first variant.

## Architecture options against this code path

| Option | Signal and action | Fit to Wan/DiTraj today | Decision |
|---|---|---|---|
| **Decoded predicted-clean state feedback** | Decode current `x0_hat`; estimate object state; apply signed residual to future foreground attention boxes. | Scheduler capture and box/mask mutation are already staged. M0 has demonstrated predicted-clean previews on a T4; actual DiTraj feedback runtime and peak memory remain unverified. No autograd or weight training. | **Run first, after the open-loop and measurement gates.** It is causal and smallest, but external-RGB-observed and only a one-update controller. |
| **Repeated observer/MPC-style updates** | Read `x0_hat` at two or more checkpoints, re-estimate the entire future path, update later boxes repeatedly. | Same hook could support it, but repeated full VAE decodes add cost and successive estimates are alternate predictions of one sample, not independent video observations. A late checkpoint also leaves little denoising horizon. | Defer. Start with one update; add a second checkpoint only after measuring the first update's effect. |
| **Learned latent state head + bounded control** | Keep Wan's spatial token grid; predict center/extent/visibility/confidence from layer/step features; apply the same residual law without RGB decode. | M0 currently stores only spatially pooled per-frame means/stds (`[1,5,1536]`-style summaries), so it has discarded the location signal needed for localization. The capture hook can be extended to retain a low-resolution grid, but no labels or trained head exist. | Best route to a *native latent observer* after a decoded-state teacher passes. Linear probe first; only then a tiny temporal head. Not the first control experiment. |
| **Q/K feature or attention controller** | Estimate cross-frame point/region correspondence from selected Wan queries/keys; modify attention or infer target-relative drift. | M0's processor stores entropy and frame-mass statistics for only 16 uniformly sampled queries against all keys, not point correspondence or object location. DiffTrack demonstrates that selected DiT Q/K layers can carry correspondences, but its evaluated backbones are CogVideoX/HunyuanVideo, not this Wan 1.3B path. | Useful observer/teacher research if spatial latent probes fail. Needs a new correspondence capture and Wan-specific validation. Do not call current attention summaries a usable tracker. |
| **Differentiable reward / latent optimization** | Backpropagate a path loss through predicted-clean estimation and possibly the VAE, then change `z_t` or velocity. | Current runner wraps the pipeline in `torch.inference_mode()` ([runner line 142](run_ditraj_feedback_pilot.py#L142)). That is incompatible with gradients; nesting `torch.enable_grad()` does not make inference tensors differentiable. Wan's denoiser/VAE graph would also raise memory sharply. A discrete red threshold has no useful gradient. | Do not use on the T4 pilot. A later attempt needs a differentiable object-state reward, a compatible sampling update, and a fresh memory/performance design. |
| **Teacher-to-policy distillation** | Label generated states/actions with simulator truth or an independent track/segmentation teacher; train a compact latent head/controller to imitate state or corrections. | No generated-state/action corpus exists; current synthetic calibration is only two correlated sphere paths, and current red observer is unvalidated on DiTraj outputs. | Future direction once the online teacher/controller has a repeatable benefit. Distill state first, not the whole 40-block generator. |
| **LoRA / DPO / GRPO or learned control module** | Change Wan weights or attach a trained adapter using trajectory/reward supervision. | No adequate object-path preference/training set is present. Large-scale VGGRPO reports about 1,536 GPU hours; a small LoRA experiment would still need to establish data, training stability, and held-out generalization. | Not justified before a held-out inference-time gain. Weight changes make causal diagnosis and regression control harder at this stage. |
| **Best-of-N or particle search** | Generate several candidate videos and pick by path/physics score. | Simple as a later quality upper bound, but scales generation cost by candidate count and selects samples rather than steering a single trajectory. | Keep separate as a search baseline; it is not evidence for an in-sample feedback gate. |

### Recommended staged architecture

**Stage 0: measurement and base control.** Complete double-label reliability, then run matched no-control / foreground-background separation / full DiTraj on mirrored paths and shared noise. Keep path direction out of prompt text. Score blinded boxes, identity, visibility, duplicate count, extent, and background stability. This establishes the actual DiTraj control distribution before adding policy logic.

**Stage 1: one-read causal action.** In the DiTraj run, decode step-4 `x0_hat`, estimate all-frame centers, and update the four unlocked future control boxes by a preregistered gain/cap. Keep first-three-step hard RoPE identical. Stage the existing three-arm one-direction 8-step mechanism smoke first; only after it passes and T4 memory is known should it expand to 30 steps and mirrored held-out seeds.

**Stage 2: causal controls and efficacy.** The primary contrast is full DiTraj versus full DiTraj + state feedback. Mechanism controls should include: same decode/observer but zero gain; feedback with the measured residual; sign-reversed residual; waypoint-shuffled residual; and a fixed open-loop offset learned only on development samples and matched to the feedback arm's mean action magnitude. Use identical prompt, shared initial noise, sampler, CFG, denoiser-call count, decode checkpoints, and observer path. A gain that survives zeroed/shuffled state or is matched by a fixed offset is not evidence for state feedback. Run multiple paired seeds on left/right paths, then one held-out stop/turn path. Keep the Gate 0 scorer independent of the red observer.

**Stage 3: latentize the observer.** On generated videos with independent box labels, save spatial features from selected Wan blocks/time steps, not only `[B,F,D]` spatial means/stds. Start with a linear position probe and compare it to the decoded teacher and constant/prompt-only baselines on held-out seeds and trajectories. If location is observable, train a small temporal head for center and scoreability/confidence, distilling the teacher's state. Keep the controller law fixed initially so state-estimator changes are isolated from action-learning changes. Only later learn a bounded action head or attach a small attention/control adapter. Evaluate with human boxes or simulator ground truth rather than the same teacher used for supervision.

## Primary literature: what is established and what it rules out

- **DiTraj** is the exact open-loop baseline: it uses foreground/background prompt separation and early spatial-temporal RoPE alignment for box-path control; its stated goal is training-free path control on a video DiT. It explicitly changes attention/position guidance based on the supplied target boxes, not on an observed state residual. This makes it appropriate as baseline but means box conditioning and mask updates alone are not new. [Paper, Sections 3.2–3.4](https://arxiv.org/html/2509.21839v2); [official repository at pinned commit](https://github.com/xduzhangjiayu/DiTraj/tree/6fa8e613c9e7c40ec2db456ab2ba34367a076886).
- **SG-I2V** optimizes noisy latents using SVD feature similarity along desired box trajectories and adds frequency-based post-processing to limit quality degradation. This already occupies generic feature-based trajectory guidance and iterative latent correction; it is U-Net/SVD-based I2V, not the current Wan T2V DiT path. Our test must be specifically about a measured current-state residual changing a later DiTraj control update. [Paper, Sections 3.2–3.4](https://arxiv.org/html/2411.04989v3).
- **Frame Guidance** uses predicted-clean estimates, gradients of frame-level control losses, latent optimization, and temporal slicing; the appendix gives a flow-matching/Wan procedure. It is direct prior art for “predicted clean + guidance.” The paper reports that a naïve guidance graph can exceed 650 GB even with checkpointing, with the CausalVAE as a major contributor; its Wan experiments use 14B and 2× spatial downsampling. This does not prove a 1.3B single-sample gradient cannot fit, but it is a poor first T4 bet and has materially different compute semantics from our no-grad box gate. [Paper, Sections 3–4 and Appendix B](https://arxiv.org/html/2506.07177v2).
- **DiffTrack** extracts point correspondences from video-DiT Q/K and uses cross-attention guidance for motion enhancement without training. This is a strong internal-feature/attention collision. The paper evaluates CogVideoX and HunyuanVideo, not Wan 1.3B. Porting selected Q/K correspondences could later be a native observer, but the M0 summaries are not the paper's point tracker. [Paper](https://arxiv.org/html/2506.17220); [official code](https://github.com/cvlab-kaist/DiffTrack).
- **VGGRPO** trains a latent geometry model (a 3D convolutional stitcher over a geometry teacher), applies LoRA GRPO, and separately presents test-time reward gradients on latent states. The paper reports a 20-epoch LGM training mix of generated clips plus DL3DV, RealEstate10K, MiraData; Wan2.1-1B and Wan2.2-5B LoRA with group size 64; roughly 1,536 GPU-hours for VGGRPO. Its test-time reward updates velocity from latent geometry, every 20 of 50 steps in its reported setting. These are relevant templates but its camera-smoothness and geometric-reprojection rewards do not directly measure a moving object's commanded path, and the measured reward-computation table uses batch 4 with 68.57 GB peak GPU memory. Reproduce none of that as the first local policy. [Paper, Section 4 and Appendix B](https://arxiv.org/html/2603.26599v2).
- **WMReward** uses V-JEPA-2 as a physics prior and evaluates best-of-N/gradient variants on vLDM-5B, MAGI-1 24B and other larger systems; its PhysicsIQ search uses 16 particles. It supports latent-world-model reward search as a later physics-policy branch, but no result establishes T4 fit or object-pixel path correction for this route. [Paper](https://arxiv.org/html/2601.10553).

The evidence supports using feedback as a testable control hypothesis, not claiming a broad new “self-correcting video diffusion” paradigm. Related work already claims latent trajectory optimization, predicted-clean guidance, Q/K tracking, reward-gradient guidance, and generated-video self-refinement. Any eventual novelty statement must specify the state source, action channel, feedback timing, and demonstrated held-out effect.

## Local implementation details and technical blockers

1. **M0 is not a latent tracker.** `m0/run_m0.py` captures transformer-block outputs but pools each token grid to spatial mean/std per latent frame (`block_hook`, around lines 276–308). The M0 attention instrumentation materializes statistics for 16 sampled queries against all tokens and saves entropy/frame mass, not spatial correspondences (`BoundedWanSelfAttentionProcessor`, around lines 452–540). The saved summary shape therefore cannot locate the object. Save spatially indexed activations in a future observer capture.
2. **The feedback controller is specifically 17-frame.** `OBSERVATION_FRAMES=(0,4,8,12,16)` is hard-coded in [the adapter](ditraj_feedback_adapter.py#L28), and initialization requires exactly five boxes. A longer Wan video needs an explicit VAE-time/frame mapping and temporal resampling; do not silently reuse it.
3. **The target mask is a coarse actuator.** Continuous boxes are floored into a 52×30 grid by [the adapter rasterizer](ditraj_feedback_adapter.py#L132). Fractional one-cell shifts can change only one edge or change the occupied area asymmetrically. Record token-grid centers, changed cells, per-box area, and IoU; for later tests, consider representing action directly as integer token shifts so the intervention does not accidentally alter extent.
4. **The RGB observer is not production-quality state estimation.** It unions all red pixels in a frame. The 0.65 stability cutoff was picked on two correlated synthetic development paths and is explicitly not calibrated. Anchor subtraction cancels fixed centroid bias but may hide a real start-position mismatch. Validate raw start error separately and use independent labels, not this detector, for primary scoring.
5. **Autograd is not a drop-in extension.** The runner executes `pipe(...)` inside `torch.inference_mode()` ([line 142](run_ditraj_feedback_pilot.py#L142)). Any VGGRPO/Frame-Guidance-style loss gradient needs a different execution mode, differentiable objective, graph retention strategy, and compatible scheduler update; `enable_grad` nested inside inference mode is insufficient. UniPC is a multistep solver with stored converted predictions, unlike the simple Euler update shown in VGGRPO's pseudocode; a gradient-modified velocity path must verify the effect on solver history.
6. **T4 memory is not proven by the M0 run.** M0's saved sample shows that the separate Diffusers 0.40 Wan microscope decoded step-4 predicted-clean frames on a T4. The staged controller uses pinned DiTraj/Diffusers 0.33.1, custom attention code, model CPU offload, and an intermediate VAE decode before reloading the transformer. Measure end-to-end peak allocation and wall time on that exact route. The `AutoencoderKLWan.decode` forward hook should make device placement work, but VAE/transformer co-residency after intermediate decode is still an empirical memory gate.
7. **No policy effect has been measured.** Local CPU checks and the exact UniPC conversion smoke establish controller/source mechanics only. There is no GPU DiTraj output, action-response curve, held-out trajectory score, or improvement delta. The current cloud draft/state is separately recorded as incomplete; no T4 run should be inferred from M0.

## Decision gates

Proceed only in this order:

1. Finish the annotation reliability check and run matched mirrored-path baseline / SG / full DiTraj.
2. Stage and review the exact feedback runner; run only the 8-step baseline / decode-matched no-op / feedback mechanism smoke after a fresh free-T4 preflight. Confirm exact no-op output equality, a rasterized mask change for feedback, VAE coverage, and peak memory.
3. If the mechanism smoke fits, use the full 30-step schedule and preregister fixed gain/cap. Run matched held-out left/right paths and seeds with state shuffle, sign reversal, zero-gain, and fixed open-loop-action controls.
4. If feedback wins without guardrail regressions, collect spatial Wan features and train a small latent state readout. Do not mix state-head training with action-law tuning in the first latentized comparison.
5. Only after a measured latent state probe and repeated feedback benefit consider a learned action head, a small native attention adapter, teacher distillation, LoRA, or reward-gradient policies.

**Stop rule:** if path adherence is not scoreable, the decoded observer fails independent localization, an open-loop fixed action matches feedback, or the T4 cannot sustain the exact three-arm loop, stop this controller branch and revisit the observer or compute design rather than expanding the model-training scope.
