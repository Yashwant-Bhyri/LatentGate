# Gate 1 follow-up: frame labels, identity, and human agreement

**Date:** 2026-10-03 (Asia/Shanghai)  
**Component:** 1 — Object measurement  
**Decision:** use blinded, manual, framewise tight-box labels as the reference. Keep machine proposals secondary and out of annotators' view. The online path metric uses the tight-box midpoint; visibility, instance count, identity, background stability, and apparent size remain separate measurements.

## Why Gate 1 is still open

The synthetic scorer check establishes coordinate conventions and arithmetic, not human-label reliability. Inspection of `research/kubric_gate0_annotation_reliability/package_manifest.json` found that the two current v2 rater ZIPs each contain the same 17-frame `right` sequence. The existing package therefore cannot check agreement across mirrored motion. The saved M0 annotation ZIP also placed both duplicate aliases in one archive; each rater now has a separate packet containing the same pixels under one shared blind ID.

The new synthetic packets each contain the existing 17-frame left/right Kubric mirror pair (34 frame labels). This is a **process screen**, not the complete pre-registered reliability gate: there is only one rendered pair, while the project plan requires two independent mirrored-seed blocks. No labels have been returned. Both the synthetic and M0 CSV templates are still blank.

## Annotation independence correction (2026-10-11)

A source audit found that the v3 annotation UI could manufacture agreement on its scored categorical fields: drawing a box silently set visibility to Yes, instance count to 1, and identity to Yes; choosing visibility No silently set count to 0 and identity to No. This violates the intended independent framewise annotation of visibility, count, identity, and box geometry. The earlier synthetic v3 UI smoke exercised these defaults and is not evidence that the categorical fields were independently judged.

The v3 ZIPs are preserved with their archive hashes but are marked superseded; do not distribute or score them for the Gate 1 screen. The packet builder now creates v4 at [`gate1_manual_annotation_packets_v4`](gate1_manual_annotation_packets_v4/README.md). Drawing only changes box coordinates, and changing visibility changes only that field. For an absent target, the annotator must separately mark visibility No, enter count 0, mark identity No / uncertain, and leave the box empty. Inconsistent combinations remain incomplete until each field is corrected explicitly.

A synthetic browser smoke of isolated copies of v4's rater-01 page confirmed that (a) setting visibility No left count and identity blank; (b) drawing a box did not fill any categorical field; (c) switching visibility to Yes left count and identity blank; (d) manually entering count and identity completed the frame; (e) values persisted across reload; and (f) switching visibility back to No left the manually entered count, identity, and box unchanged. A fresh packet key in standard Chrome then exported 34 rows with one deliberately synthetic absent-state row and 33 blank rows: [`smoke_export_intentionally_invalid_not_for_scoring.csv`](qa/gate1_v4_ui_roundtrip/smoke_export_intentionally_invalid_not_for_scoring.csv). That test row contradicts the visible object and is invalid as an annotation of the frame; it exists only to test CSV serialization. Automated CSV import/resume could not be verified because the Chrome extension disallows local-file access; no permission was changed. See [`the independence audit`](2026-10-11_gate1_annotation_independence_audit.md).

The CSV scorer now also rejects an absent row marked identity-consistent/Yes, so manually filled fallback CSVs must honor the absent-target ontology. The synthetic CPU check accepted `visible=false, count=0, identity=false, no box` and rejected `visible=false, count=0, identity=true, no box`; result: [`gate1_absent_identity_guard_v1.json`](gate1_absent_identity_guard_v1.json). This verifies one semantic input guard, not rater reliability.

Latest pre-v4 return scan: all four v3 packet templates were blank (synthetic 0/34 per rater; M0 0/17 per rater), with no separate human-return CSV. No v4 labels have been collected. Send the v4 synthetic pair to two independent raters and collect new submissions; any v3 return must not be included in the reliability score. One passing left/right pair remains only a process screen; full reference reliability still requires another independently rendered mirror block.

### Measurement conclusion

Benchmarks across video segmentation, occluded instance tracking, and arbitrary point tracking agree on three useful separations: (1) center/localization error, (2) visibility and identity, and (3) mask extent/boundary. They do not provide a ready-made metric that establishes whether a diffusion-generated object follows a commanded image-plane path. Use the existing custom score for the path; use human labels as independent reference; retain masks/size and background stability as guardrails. Sample every rendered frame, do not linearly fill the annotations, and never choose a detection by its closeness to the requested path.

## Tool and artifact decision

I prepared a small self-contained annotation page rather than installing CVAT or requiring a hosted labeling service. It embeds the packet images, runs locally in the browser, makes no network calls, supports manual rectangle drawing on each frame, captures explicit visibility/count/identity fields, persists work locally where browser storage is allowed, and imports/exports the scorer's existing CSV schema. Keyboard navigation and a visible frame strip support sequential review. Every bounding box is still drawn by the annotator on that frame; the tool never propagates or interpolates boxes.

## Scorer tail diagnostic (2026-10-03)

Before labels were available, I checked whether a pooled 95th percentile could hide a weak mirrored direction. The reproducible CPU-only scenario in [`validate_gate1_agreement_scorer.py`](validate_gate1_agreement_scorer.py) creates two 17-frame synthetic clips with exact categorical agreement, zero center disagreement on the right, and 15 px horizontal disagreement on two left frames. The pooled center-distance p95 is 5.25 px and passes the 8 px threshold, while the left-only p95 is 15 px and fails. The scorer now reports the worst center-disagreement frame and requires the pooled result **and each clip** to pass, so the overall screen correctly fails. The maximum is displayed for review but is not a new threshold.

## Expected-clip completeness guard (2026-10-04)

The follow-up code audit found a second fail-open case: the scorer required all 17 frames for every clip that appeared in the CSVs, but did not require the packet's full clip count. If both raters omitted one mirrored clip, the remaining clip could still produce a passing report. The CLI now requires `--expected-clips`; use `2` for the paired Kubric screen and `1` for the single-clip M0 observer check. The scorer rejects input with the wrong number of distinct clip IDs before calculating agreement.

The updated [`CPU diagnostic`](gate1_scorer_tail_diagnostic_v2.json) covers both guards: the pooled p95 still passes while a direction-specific p95 fails, and a one-clip submission is rejected when two clips are expected. Latest run took 0.000233 s of measured scorer time on Darwin arm64 CPU (Python 3.12.3); GPU use was false and peak VRAM was null/not allocated. This is synthetic scorer-validation evidence only; no human annotations or model inference were used. ## Falsifiable next step and release gate

1. Give `synthetic_reliability/rater_01.zip` and `rater_02.zip` to separate annotators. Keep `PRIVATE_UNBLIND_KEY.json` and all machine proposals private. Each annotator labels all 34 frames, one box per visible target, with no path or method information.
2. Compare their CSVs with:

   ```sh
   python3 research/score_annotation_agreement.py rater_01.csv rater_02.csv --source-width 160 --source-height 96 --expected-clips 2 --output research/gate1_synthetic_agreement_screen_v2.json
   ```

   Screen: joint visibility/count/identity agreement at least 95%, at least 90% of frame pairs with a uniquely visible box from both raters, and p95 absolute tight-box-midpoint disagreement no more than 0.5 **target-grid cell** on either axis after scaling source coordinates to 832×480 / 52×30. For the 160×96 Kubric packet, that equals 1.5385 raw x-px and 1.6 raw y-px; never compare its raw pixels directly with the 16 px target cell. Require the pooled result **and each mirrored clip** to pass; a pooled score must not hide a direction-specific labeling problem. The scorer reports target-resolution pixel and cell metrics plus the source-pixel values. With only 17 frames per clip, linear-interpolated p95 is `sorted[15] * 0.8 + sorted[16] * 0.2`; for example, a 6 target-px second-worst error and 15 target-px worst error yield a 7.8 target-px (0.4875-cell) p95. A new [tail-sensitivity audit](2026-10-11_gate1_p95_tail_sensitivity.md) confirms that one 2.5-cell outlier among the full 34-frame pair can still pass pooled and per-clip p95. Therefore, inspect and record each clip's maximum radial center-error frame and per-axis maximum frames if different, even when p95 passes; this is a review requirement, not a new numeric threshold. Do not treat frames as independent seeds. Any threshold failure triggers ontology/instruction repair and relabeling.
3. Even if this one-pair screen passes, it does **not** close the planned two-block human-reliability gate. Add a second independently rendered mirrored block and double-label it before calling the reference reliable. After that, independently double-label the separate M0 convenience sample and compare red/SAM2 proposals to the human boxes. A single generated clip is not the held-out observer gate and cannot establish policy efficacy.

   For the separate single-clip M0 convenience check, pass `--expected-clips 1`. Do not use that result to pass the synthetic reliability gate.

This next step is falsifiable: the measured inter-rater state agreement and p95 center disagreement either meet the declared thresholds or they do not. Until then, component 1 remains open, and no policy or observer gain is claimed.


## Coordinate-resolution correction (2026-10-11)

The synthetic Kubric frames embedded in the v4 packets are 160×96 and the annotator exports raw source-frame pixels. The former scorer's `--cell-px 16` divided those coordinates by a Wan-resolution cell without resizing or normalizing; this made the raw 8 px tolerance equal 2.6 x-cells and 2.5 y-cells. The updated v2 scorer requires `--source-width` / `--source-height`, maps each axis to the 832×480 target and then to the 52×30 grid, and validates source-frame box bounds. The old v1/v2 CPU diagnostic files remain historical synthetic arithmetic checks; they contain no human data. New scorer behavior is recorded in [`2026-10-11_gate1_coordinate_scale_audit.md`](2026-10-11_gate1_coordinate_scale_audit.md) and [`gate1_scorer_tail_diagnostic_v3.json`](gate1_scorer_tail_diagnostic_v3.json). No v4 packets were modified, and no labels were discarded because none had been returned.
