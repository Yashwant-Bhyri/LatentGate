# Future DiTraj output annotation adapter contract

**Status:** specification only; no packet, adapter code, labels, or generated-output scores exist. This contract is separate from Gate 1 v5 and from the DiTraj action-to-measurement audit.

## Release prerequisites

Do not create this packet or score DiTraj outputs until:

1. Two independent, complete Gate 1 v5 human returns pass exact packet-map validation, pooled and per-clip agreement, blind worst-frame review, and guarded Kubric truth scoring. Intake scan v7 (2026-10-16 06:48:03 UTC) found zero complete or partial human returns; the gate is closed.
2. A fresh no-paid compute admission and the existing runtime/source gates pass.
3. The registered six-case experiment has produced six complete, artifact-verified 17-frame outputs at the planned full inference schedule. The one-step mechanism smoke alone is not a scoreable video-quality batch.
4. The blind labeling instructions, target-path scoring reference, image manifest, and separate path/visibility/identity/size/background measures are frozen before the packet is distributed.

## Packet and frame-map contract

- Six outputs × 17 decoded RGB frames = exactly 102 frames. Expected output dimensions are 832×480; retain the original PNG pixels and source-space coordinates.
- Assign six opaque random `blind_clip_id` values. The annotator ZIP may contain only blind IDs and image files with neutral names such as `frame_000.png`…`frame_016.png`; omit arm, path-direction, seed, run-key, and prompt-condition names.
- Bind each frame with one immutable record: `blind_clip_id`, `frame_index` (integer 0–16), `image_file` (relative path), `sha256`, `width`, and `height`. The 102 `(blind_clip_id, frame_index)` keys and 102 image paths must each be unique. Keep a packet hash and the exact key-to-image map as the scorer's reference.
- Each rater CSV must have exactly one row for every reference key and preserve the exact `image_file`. Require exactly six blind IDs and the complete frame set 0–16 for each. Reject missing/extra/duplicate keys, duplicate image paths, map/hash/dimension mismatches, decode failures, or a changed packet hash. Never interpolate a missing row or silently repair a filename.
- Store the alias-to-run/arm key outside the packet and outside the adapter/scorer inputs. The adapter must refuse any private/unblind-key file, key path argument, arm/run/direction field, or filename that exposes a condition. An evaluator-only blind reference may map each blind ID to its normalized per-frame target boxes for path scoring, but must not contain arm/run labels and must never be sent to raters.

## Implementation-ready artifact schemas (specification only)

This addendum freezes the data contract for a future packet builder; it does not authorize packet creation, scoring, or release. No manifest or background-evidence artifact exists yet. Keep the six-output packet blind: no arm, run, seed, path direction, prompt, or condition metadata may appear in its ZIP members, paths, image metadata, or blank response template. Keep the scorer-side manifest, integrity receipt, condition key, annotations, and background report outside the annotator ZIP. The condition key remains unavailable to the adapter and scorer until the blinded reports are frozen.

### `frame_manifest.json`

Serialize one UTF-8 JSON object with exactly these top-level keys, in the listed order: `schema_version`, `packet_id`, `expected_clip_count`, `expected_frames_per_clip`, `pixel_format`, `width`, `height`, `frames`. Use `schema_version = "ditraj.generated_output_frame_manifest.v1"`, a newly generated lowercase canonical UUIDv4 for `packet_id`, constants `6`, `17`, `"RGB8"`, `832`, and `480`, respectively, and exactly 102 records in `frames`. Encode JSON as UTF-8 without a BOM, LF line endings, two-space indentation, and one terminal LF. Sort records by the lowercase `blind_clip_id` bytewise, then by ascending `frame_index`.

Every frame record has exactly these keys, in this order, with no additional properties:

| Key | Type and exact constraint |
|---|---|
| `blind_clip_id` | Lowercase canonical UUIDv4 generated from operating-system cryptographic randomness after the six outputs are fixed; unique per output and unrelated to run, arm, path, seed, or prompt. Never reuse an ID. |
| `frame_index` | JSON integer (a boolean is invalid), 0 through 16 inclusive. |
| `image_file` | Normalized POSIX relative path exactly `images/<blind_clip_id>/frame_<frame_index padded to 3 digits>.png`; no absolute path, `.`/`..`, backslash, URL, NUL, or path alias. |
| `sha256` | Lowercase 64-character hexadecimal SHA-256 of the exact PNG member bytes, before decoding. |
| `width` | Integer exactly `832`, verified from the decoded image. |
| `height` | Integer exactly `480`, verified from the decoded image. |

The referenced member must decode as 832×480, 8-bit-per-channel RGB PNG with three channels and no alpha. Preserve the decoded RGB pixels; do not resize, color-correct, stabilize, or re-encode for measurement. The ZIP contains exactly the 102 expected PNG file members (directory entries may be omitted); reject duplicate member names, symlink members, and any extra file. The blank response template, if distributed, is a separate file and may contain only the registered blind keys and annotation fields, never run conditions.

Create a separate evaluator-side `packet_integrity.json` after the archive is finalized. It contains exactly `schema_version`, `packet_id`, `frame_manifest_sha256`, `annotator_archive_sha256`, and `frame_count`, with `schema_version = "ditraj.packet_integrity.v1"` and `frame_count = 102`. Hash the exact serialized `frame_manifest.json` bytes and exact finalized ZIP bytes; store both as lowercase 64-character SHA-256 strings. This avoids a self-referential packet hash and binds the scorer reference to the exact archive. Neither the manifest nor integrity receipt is included in the annotator ZIP.

The packet builder/validator must fail closed unless all of the following hold: the JSON has the exact keys/types/constants above; there are exactly six distinct UUIDv4 blind IDs and exactly 17 records for each; the key set equals the Cartesian product of those six IDs and indices 0–16; all 102 keys and all 102 normalized paths are unique; every path equals the prescribed ID/index path and resolves to exactly one regular ZIP member; the ZIP regular-file set equals that expected path set; each member's bytes match its row SHA-256; each decoded PNG matches the required RGB8 format and recorded dimensions; and both detached hashes match the finalized files. Reject missing, extra, duplicate, malformed, mismatched, or unlisted content without repair, interpolation, path rewriting, or partial scoring. A repeated PNG hash on distinct frame keys is retained as two distinct observations and flagged as an exact-frame-duplicate diagnostic; it does not permit path aliasing or row collapse. To make metadata screening deterministic, allow PNG chunks only from `IHDR`, `PLTE`, `IDAT`, `IEND`, `sRGB`, `gAMA`, `cHRM`, or `pHYs`; reject text, EXIF, unknown chunks, ZIP comments, extra fields, or any condition-bearing names. Refuse the packet if any condition is exposed.

### `background_stability_evidence.json`

Keep this evaluator-side artifact separate from the annotator ZIP, response CSVs, and condition key. Its schema version is `ditraj.background_stability_evidence.v1`. It is blind and keyed only by `packet_id` and the six `blind_clip_id` values. It must bind to `frame_manifest_sha256` and record hashes/versions for the method memo, calibration preregistration, measurement code, measurement configuration, source export when present, decoded-frame inputs, and target-exclusion masks. Store the completed report's own SHA-256 in a detached evaluator-side integrity receipt or registry entry, not inside the report itself. Record whether the source was direct RGB frames or a video; for video, retain container, codec/profile, pixel format/chroma, frame cadence/time base, encoder settings when available, and decoder/version. For each clip, record the two frozen blinded-annotation input hashes, the 832×480 binary ROI-mask hash, mask construction (`union_of_both_raters_valid_boxes_over_all_17_frames_plus_frozen_calibrated_halo`), calibrated halo in source pixels, retained/excluded ROI fractions, and the hashes of the frozen flow/appearance settings. Do not copy raw labels or arm/run/seed/path metadata into this report.

The JSON object has exactly these top-level keys: `schema_version`, `status`, `packet_id`, `frame_manifest_sha256`, `provenance`, `calibration`, and `clips`. `status` is `descriptive_only_threshold_pending` until a versioned calibration freeze exists; it may then be `calibrated_thresholds_frozen`. `provenance` contains `method_memo_sha256`, `calibration_preregistration_sha256`, `measurement_code_sha256`, `measurement_config_sha256`, `python_version`, `opencv_version`, `decoded_frame_manifest_sha256`, and `source`. `source` contains `kind` (`direct_rgb_frames` or `video`), `source_export_sha256` (lowercase SHA-256 or null for direct frames), `decoder_name`, `decoder_version`, `decoder_config_sha256`, `container`, `codec_profile`, `pixel_format_chroma`, `frame_rate`, `time_base`, `encoder_settings_sha256`, and `color_metadata`; video-specific values are null when `kind` is `direct_rgb_frames`. All hashes are lowercase 64-character SHA-256 strings.

`calibration` contains exactly `status`, `task_tolerances`, `development_split_sha256`, `holdout_split_sha256`, `frozen_settings_sha256`, and `thresholds`. Its status is `pending` or `calibrated_frozen`; before calibration, every field except `status` is null. Once supplied by the task owner, `task_tolerances` contains exactly `task_spec_sha256`, `recorded_utc`, `minimum_material_camera_translation_px_per_frame_pair`, `maximum_acceptable_illumination_change_rgb_01`, `maximum_acceptable_luma_median_shift_dn`, and `codec_tolerance`; the first is a SHA-256, the second is an RFC 3339 UTC timestamp, the camera-motion tolerance is finite and positive, RGB tolerance is finite in [0,1], luma tolerance is finite in [0,255], and codec tolerance is a concrete profile description or the literal `not_applicable`. No values are supplied by this contract. A frozen `thresholds` object contains exactly `maximum_G_px_per_frame_pair`, `maximum_A_rgb_abs_diff_01`, `maximum_L_luma_shift_dn`, `minimum_C_accepted_track_fraction`, and `minimum_retained_roi_fraction`. Fractions are finite values in [0,1]; all other numeric values are finite and nonnegative. A frozen record must provide the task tolerances, separate development/holdout manifest hashes, frozen settings hash, and thresholds produced under the registered calibration rule. `clips` contains exactly six objects, one per unique blind ID, with exactly these fields: `blind_clip_id`, `status`, `unscoreable_reasons`, `annotation_input_sha256s` (two hashes), `roi_mask_sha256`, `mask_construction` (the literal above), `halo_radius_px`, `retained_roi_fraction`, `excluded_roi_fraction`, `transitions` (16 ordered records), `summary`, and `classification`. Clip `status` is `measured` or `unscoreable`; `unscoreable_reasons` is empty only when measured. `summary` contains only `G`, `A`, `L`, and `C`. `classification` is null while calibration is pending; after a valid freeze it is `stable`, `change`, or `unscoreable` under the frozen protocol. The object has no arm/run/seed/path fields and rejects additional properties. Validate that the six clip IDs equal the manifest IDs exactly and that each clip has the complete 0→1 through 15→16 transition set; otherwise refuse the artifact.

Each clip has exactly 16 ordered transition records (`from_frame_index` 0–15 and `to_frame_index = from_frame_index + 1`). Preserve, per transition, candidate/accepted LK-track counts and fraction, retained ROI coverage, median signed Δx/Δy, median/p95 displacement magnitude in source px per frame pair, spatial/tile coverage, raw adjacent-pair RGB channel mean/median/p95 absolute difference divided by 255, and luma median shift in DN. Also retain the frame-0-relative RGB/luma diagnostics and the full per-transition table. Missing metrics are explicit `null` with a reason/status; never turn absent flow or inadequate coverage into zero motion or a stability pass.

Each transition object has exactly these keys: `from_frame_index`, `to_frame_index`, `status`, `unscoreable_reason`, `candidate_track_count`, `accepted_track_count`, `accepted_track_fraction`, `retained_roi_fraction`, `median_dx_px`, `median_dy_px`, `median_displacement_px`, `p95_displacement_px`, `spatial_coverage`, `rgb_adjacent_abs_diff_mean_rgb_01`, `rgb_adjacent_abs_diff_median_rgb_01`, `rgb_adjacent_abs_diff_p95_rgb_01`, `luma_adjacent_median_shift_dn`, `rgb_frame0_abs_diff_mean_rgb_01`, `rgb_frame0_abs_diff_median_rgb_01`, `rgb_frame0_abs_diff_p95_rgb_01`, and `luma_frame0_median_shift_dn`. RGB vectors are ordered R,G,B. `status` is `measured` or `unscoreable`; the reason is null only when measured. `spatial_coverage` is the full array of tile records using the tile boundaries frozen in the configuration; each tile record has `x0_px`, `y0_px`, `x1_px`, `y1_px`, `roi_pixel_count`, `candidate_track_count`, `accepted_track_count`, `accepted_track_fraction`, `median_dx_px`, `median_dy_px`, and `p95_displacement_px`. Numeric measurement values are finite numbers or explicit null; invalid/non-finite JSON numbers are refused.

All provenance objects and nested records reject additional keys. Frame indices and counts are JSON integers (never booleans); counts are nonnegative. Fractions are in [0,1]. RGB vectors contain exactly three finite numbers in [0,1], ordered R,G,B. Measured transitions require null `unscoreable_reason`; unscoreable transitions require a nonempty reason. Invalid or unavailable measurements are null, never zero-filled.

Per clip, report the registered summaries separately: `G = p95_t(median_i(||d_it||_2))` in px/frame-pair, `A = p95_t(mean_ROI_RGB(|I_t-I_{t+1}|/255))`, `L = p95_t(|median_ROI(Y'_{t+1}) - median_ROI(Y'_t)|)` in DN, and `C = minimum accepted-track fraction over the 16 transitions`. Keep geometry, appearance/luma, and coverage as separate values; six clips, not their 96 transitions, are the experimental units. The report schema contains `calibration_status`, `task_tolerances`, `frozen_settings_sha256`, `development_split_sha256`, `holdout_split_sha256`, `thresholds`, and per-clip `classification`. Until task-defined minimum material camera motion and maximum acceptable illumination/codec changes exist and an independent development/untouched-holdout calibration passes, `calibration_status` is `pending`, `thresholds` and all classifications are `null`, and the report is descriptive only. Do not insert provisional numeric limits or infer them from the six evaluation clips. Any later numeric values require a versioned preregistration amendment frozen before packet creation.

The exact metric definitions and calibration decision rule remain those in the linked background protocol and preregistration; this schema adds provenance and fail-closed serialization requirements only. It does not change Gate 1, authorize use of human returns, or create evidence. The release blocker remains two independent complete Gate 1 v5 returns plus the previously registered output, no-paid admission, and calibration gates.

## Annotation fields and explicit normalization

Preserve every original CSV field verbatim. A versioned derived table may add canonical fields, but must never overwrite source values:

| Source field | Canonical use |
|---|---|
| `object_visible` | Preserve explicit per-frame visibility response. Do not infer from box presence, red pixels, or model detections. |
| `instance_count` | Preserve as a separate nonnegative integer/count response; do not infer from a detector. |
| `same_identity_as_frame_0` | Map exact, unambiguous Yes → `identity_consistent=true` and No → `false`; retain the raw source value. Preserve uncertain/unknown as null/uncertain, never coerce it to No. |
| `bbox_x1_px`, `bbox_y1_px`, `bbox_x2_px`, `bbox_y2_px` | Preserve the tight visible-object box in the original 832×480 source-pixel coordinate system. |
| `frame_index`, `image_file` | Copy exactly from the immutable packet map; these fields are not annotator-editable metadata. |

Boxes use pixel-edge coordinates with half-open right/bottom edges: `0 ≤ x1 < x2 ≤ 832` and `0 ≤ y1 < y2 ≤ 480`; all values must be finite. Do not scale coordinates to the display size. A clear visible target needs a valid box and count ≥1. A clearly absent target has no box and count 0. Uncertain or malformed labels remain explicit and are ineligible for geometry; never fabricate a center or box. The current Gate 1 boolean scorer does not accept null identity values, so this generated-output adapter must retain a nullable canonical representation and must not silently feed uncertain rows to that scorer.

## Required separate reports

- **Path adherence:** For each frame 0–16, derive the annotated box center and compare it with the evaluator-only blind target-box center at the same frame. Report signed x/y residual, radial error, endpoint/path direction response, and the eligible-frame denominator. Compute geometry only when the target is clearly visible, count is one, and identity is unambiguous. Report ineligible/missing frames separately; do not fill them with interpolated labels. Use original pixels and optionally report 52×30-cell errors (`dx_cells=dx_px/16`, `dy_cells=dy_px/16`).
- **Visibility/count/identity:** Report categorical agreement and coverage per field, including uncertain/unknown rates. Do not fold failures into a path-error average or claim identity from color/position.
- **Apparent size/shape:** Separately report eligible annotated box width, height, area, their per-clip temporal variation, and endpoint change. The commanded control rectangle is not the visible object's extent.
- **Background stability:** Keep a separate, preregistered background-region metric or blinded scene rating. The method decision and calibration plan are recorded in [`the background-stability protocol memo`](2026-10-17_ditraj_background_stability_protocol.md) and [`the calibration preregistration`](2026-10-17_ditraj_background_calibration_prereg_v1.md): target-excluded sparse background flow plus unnormalized appearance/illumination signals, with codec/decode provenance bound to the same source pixels. Numeric settings and any acceptance threshold still require separate calibration and a versioned freeze before packet creation; no numeric threshold is asserted here. Path scores cannot stand in for background stability.

## Fail-closed rules and interpretation

Refuse packet creation/scoring on a wrong packet hash or key-to-image map, any missing/duplicate/extra frame, duplicate image path/reference, invalid dimensions/hash, altered coordinates, inferred labels, missing/uncertain labels coerced to booleans, or an exposed/unblinded key. Repeated PNG hashes on distinct frame keys are retained and diagnosed as specified above, never collapsed into one row. A refusal does not get converted into a low or high model score; repair the provenance or collect an explicit human response while blind.

This future packet would measure human judgments on generated outputs, not supply Gate 1 v5 reliability evidence. Even after it is completed, a path-score difference alone cannot establish physical motion, 3D pose/contact, robust identity, or policy efficacy. Efficacy still requires the registered matched baseline/open-loop/no-op/static/live-feedback/shuffled-residual/sign-reversed arms on held-out seeds and paths, with visibility, identity, apparent size, and background reported separately.
