# Observer and benchmark research: fixed-camera 2D path drift

**Checked:** 2026-10-02  
**Question:** How do we measure whether the same generated object follows a requested image-plane path, while keeping observer error, identity failure, and camera/background motion separate from actual path drift?  
**Boundary:** This is a measurement-stack review, not a model or policy result. No model was run for this memo.

## Recommendation

Keep blinded human tight-box/center/visibility labels as the scoring reference. Use a promptable video segmenter to propose a mask and box, an independent point tracker as a motion cross-check, and sparse static-background landmarks as the primary fixed-camera check. Use dense optical flow only as a secondary diagnostic. Never use one automated observer as its own ground truth, and never choose or repair a tracked object by its proximity to the commanded path.

The newest official candidate is **SAM 3.1 Object Multiplex**, with a first-frame visual prompt (and text only as an optional secondary prompt). It supports video prompts and mask tracking, but its upstream reference install currently requires Python 3.12+, PyTorch 2.7+, and CUDA 12.6+; the documented install uses PyTorch 2.10/CUDA 12.8. Checkpoint access is gated through Hugging Face and the SAM materials use Meta's SAM License. This makes SAM 3.1 a GPU-lane candidate, not an immediate fit for the local MPS-only machine. For the first comparison, retain the already-run **SAM 2.1 tiny** observer as a measured baseline/proposal, and add SAM 3.1 only if the designated GPU runtime fits the reference stack. [SAM 3 repository and install requirements](https://github.com/facebookresearch/sam3), [SAM 3.1 release notes](https://github.com/facebookresearch/sam3/blob/main/RELEASE_SAM3p1.md), [SAM License](https://github.com/facebookresearch/sam3/blob/main/LICENSE)

For independent motion evidence, choose **CoTracker3 offline** for the short, already-rendered clips: it returns point tracks and per-frame visibility and can reason in both temporal directions. If testing occlusion and re-entry is a deliberate component, add **TAPNext++** as a second point-tracking candidate; the 2026 paper specifically addresses a re-detection weakness in earlier TAPNext and defines a re-detection metric. Neither point tracker estimates an object center by itself. [CoTracker3 paper and repository](https://arxiv.org/abs/2410.11831), [official CoTracker code](https://github.com/facebookresearch/co-tracker), [TAPNext++ paper](https://openaccess.thecvf.com/content/CVPR2026F/html/Jung_TAPNext_Whats_Next_for_Tracking_Any_Point_TAP_CVPRF_2026_paper.html), [TAP repository/checkpoints](https://github.com/google-deepmind/tapnet)

Use **Kubric/MOVi with a static camera and exact annotations** to test the observer/scorer. The MOVi data include video, per-pixel instance IDs, object image positions, boxes, visibility, depth, camera poses, and optical flow. The camera setting must be checked per variant: the family deliberately varies cameras; MOVi-C's `fixed_random` worker option is the useful fixed-view starting point, while movement variants such as MOVi-F are not fixed-camera tests. For a path-control-specific suite with known commanded trajectories, keep the existing controlled Kubric fixture and add a few independently rendered appearances/occlusion cases instead of treating random MOVi motion as the requested path. [Kubric/MOVi specification](https://github.com/google-research/kubric/blob/main/challenges/movi/README.md), [MOVi-C worker and camera options](https://github.com/google-research/kubric/blob/main/challenges/movi/movi_def_worker.py)

## What each signal actually measures

| Signal | Good use here | What it cannot establish / failure to guard against |
|---|---|---|
| **SAM 3.1 video mask/ID** | First-frame visual prompt for one instance; per-frame mask, identity continuity, optional presence and interaction corrections. Its release has the newest official promptable video stack in the sources checked. | The released VOS results are strong but mixed by dataset: SAM 3.1 improves over SAM 3 on six of seven listed VOS benchmarks, but is lower on YTVOS19 validation (89.3 vs. 89.7 J&F). Those aggregate benchmarks do not establish accuracy on generated Wan clips or accurate geometric centers. A mask can be biased, leak into a same-colored background, merge a distractor, or propagate a bad initial boundary. Object Multiplex mainly improves multi-object throughput; its reported ~7× result is at 128 objects on H100, not evidence of a single-object accuracy gain. Treat its center/box as a proposal. [Release table and scope](https://github.com/facebookresearch/sam3/blob/main/RELEASE_SAM3p1.md) |
| **SAM 2.1 tiny mask** | Locally runnable and already benchmarked on the exact project Kubric fixture; retain for cross-comparison and human-label proposals. | The existing two-mirror probe obtained full coverage but mean mask IoU 0.750, mean tight-box-center error 2.64/2.73 px, and about 1.30× ground-truth area. It had a repeatable +2.5 px vertical bias, which maps to about 12.5 Wan pixels and exceeds this project's 8 px half-cell bound. The M0 agreement is against a red-threshold proxy, not independent truth. It does not pass as an uncorrected control observer. [Local probe report](2026-10-02_sam2_observer_probe_report.md) |
| **CoTracker3 offline point tracks** | Track several query points sampled on the target in frame 0; record each point's visibility and forward/backward consistency. Use their coherent translation as an independent alert that the mask center moved implausibly. Offline CoTracker3 is the better fit when all frames are available; its repository says the offline version handles occluded and long-term visible points better than the online version. | Tracks *surface points*. A point on a rotating ball moves around its projected surface even if the geometric center follows a simple path; a smooth, textureless ball may not have a stable appearance point. Tracking a point is not identity segmentation and cannot distinguish a point that jumped to a similar-looking distractor without visual review. [Official quick start and variant notes](https://github.com/facebookresearch/co-tracker), [paper](https://arxiv.org/abs/2410.11831) |
| **TAPNext++** | Optional long-horizon / occlusion-reappearance cross-check. It tracks a queried physical surface point and predicts visibility; the latest work calls out point re-detection after occlusion or leaving the frame as an under-measured failure and adds Re-Detection Average Jaccard. | Still a point tracker, not a mask, object-level center, or multi-object identity benchmark. Its improvements do not eliminate the need to check its predictions on our short generated videos. TAP-Vid's point tracks are material surface locations, not the center of mass. [TAPNext++ paper](https://openaccess.thecvf.com/content/CVPR2026F/html/Jung_TAPNext_Whats_Next_for_Tracking_Any_Point_TAP_CVPRF_2026_paper.html), [TAP-Vid benchmark](https://tapvid.github.io/) |
| **SEA-RAFT dense flow** | Secondary camera/background diagnostic and a convenient per-pixel motion proposal; evaluate its flow EPE against Kubric's known flow. The official project reports improved accuracy/cross-dataset performance versus prior RAFT baselines and exposes custom inference including flow uncertainty. [Code and paper](https://github.com/princeton-vl/SEA-RAFT) | Pairwise pixel correspondence does not provide object ID or a globally stable trajectory; summing pairwise flow can drift. Occlusion, motion blur, low-texture tabletop, repeated patterns, and disocclusion make flow weak or undefined. Low flow over a blank surface cannot prove a fixed camera. Do not subtract a fitted camera transform from the primary path score. |
| **Human frame labels** | Reference for target ID, presence/visibility, tight box and its midpoint, ambiguous frames, and background landmarks. Two blind labelers let us measure whether the proposed observer meets the resolution needed by the control cell. | Annotator disagreement, edge ambiguity, and a loose center definition remain possible. State whether labels describe visible tight-box midpoint or another target reference point; adjudicate disagreement without seeing baseline/intervention identity where practicable. |

SAM 3's repository gives the exact current video API pattern: build `build_sam3_video_predictor`, start a session on a JPEG folder or MP4, add a text prompt on a selected frame, then read the outputs; the SAM 3.1 release links a dedicated example with text and point prompts and Object Multiplex. Use the frame-0 visual prompt for one named target, not category text alone when duplicate same-category objects are present. Keep the same prompt convention across all samples, save raw masks/IDs/confidences, and do not add later correction prompts to a scored run unless the benchmark explicitly counts those interactions. [Official inference entry points](https://github.com/facebookresearch/sam3), [SAM 3.1 video example](https://github.com/facebookresearch/sam3/blob/main/examples/sam3.1_video_predictor_example.ipynb)

The point-tracking protocols are valuable for observer calibration, not for replacing path scoring. TAP-Vid reports visible-point position accuracy at thresholds, occlusion accuracy, and Average Jaccard, which couples localization with visibility; TAPNext++ adds re-detection scoring. CoTracker3's API returns `pred_tracks` and `pred_visibility`. For the path task, report time-aligned center error separately from object visibility/identity and mask quality. If the benchmark later controls several objects, add HOTA/association metrics; a single preselected target does not need a full multi-object tracking score. [TAP-Vid metrics and repo](https://github.com/google-deepmind/tapnet), [TrackEval/HOTA](https://github.com/JonathonLuiten/TrackEval)

## Small reproducible evaluation stack

1. **Freeze the object reference point and image coordinates.** Preserve native output timestamps; map pixel centers, boxes, and normalized Kubric coordinates into one documented convention before any resizing. For this current round, follow the project measurement contract: the human target location is the tight-box midpoint; the synthetic reference also records the exact projected object center. Report start localization independently. Do not re-anchor the observed clip to the commanded first point or use dynamic-time warping.
2. **Build known-truth clips.** Reuse the existing paired 17-frame static-camera Kubric mirror fixture. Add a small frozen calibration subset with a different background/target appearance, one visually similar distractor, and a separately flagged occlusion/re-entry case. Save rendered RGB, target ID, exact per-frame instance mask, projected center, box, visibility, camera pose, and flow. MOVi-C/Kubric is useful for realistic textured assets and rich truth labels, but either filter for fixed camera or render with its `fixed_random` camera mode. Keep simple red-ball cases because that is the current generated-video target. [MOVi fields and camera options](https://github.com/google-research/kubric/blob/main/challenges/movi/README.md)
3. **Measure the automated proposals before any policy scoring.** Run SAM 2.1 tiny on local MPS and SAM 3.1 on the GPU lane if its install is available. Compare mask IoU/J&F, mask area ratio, tight-box midpoint error, frame coverage, false presence, duplicate/wrong ID, and center bias against exact Kubric labels. Run CoTracker3 offline on fixed target query points; measure TAP-Vid-style visible-point accuracy and visibility separately. Evaluate SEA-RAFT flow EPE on known Kubric flow, but retain it only as a background diagnostic if it cannot beat sparse background landmarks. Freeze model revisions, preprocessing, prompts, coordinate transforms, and thresholds from development cases before held-out generated clips.
4. **Blind human adjudication on generated frames.** On the current 17-frame samples, two raters independently label all frames for target identity, visible/occluded/out-of-frame state, tight box, center, and ambiguity; also label at least three static background landmarks. Do not show model labels or treatment names in the first pass. Reconcile identity/presence disagreement and center disagreements beyond the gate. The existing project gate is already specified: on two double-labeled mirrored seed blocks require at least 95% agreement on visibility/count/identity and human-human p95 center disagreement no more than 0.5 target-grid cell per axis (8 px at 832×480). For synthetic 160×96 Kubric packets, map source coordinates per axis before applying that threshold (1.5385 raw x-px / 1.6 raw y-px); do not compare raw pixels directly with the target cell size. Use three development blocks to freeze settings, then five fresh held-out blocks for the locked observer check. Require held-out observer coverage of at least 90% on uniquely visible frames and at least 4/5 accepted control anchors per clip; median center error no more than 0.5 cell/axis, p90 no more than 1 cell/axis, and zero accepted wrong-identity/duplicate/absent detections at control anchors. This is the existing project's preregistered gate, not a new threshold proposal. [Current component plan](2d_path_policy_component_plan.md)
5. **Keep the policy score denominator honest.** Use the project's normalized, time-aligned per-frame center error, including its predeclared maximum error for missing target frames. Report coverage, endpoint error, signed direction response, and target box/shape/size as separate fields. Report background landmark displacement (median and p95) separately; do not compensate for camera movement in the primary score. A missing target, duplicate, or wrong identity remains a failure rather than disappearing from the mean. Do not pool frames as independent samples; the case/seed is the analysis unit. [Fixed-camera evaluation audit](2026-10-02_fixed_camera_path_evaluation_audit.md)

### Ordered calibration gates

**Gate A — geometry and scorer:** Run the existing known-GT Kubric scorer after resize/normalization round trips and both mirrored paths. Require correct coordinate order, timestamps, object IDs, visible/absent accounting, and no camera motion; retain exact mask, center, and landmark truth. The local scorer has already passed its deterministic/rendered fixture checks, but broader observer calibration remains open.

**Gate B — observer proposal:** On held-out known-GT variants, compare raw automated outputs to truth without path-based selection. Evaluate first-frame localization separately, not only relative movement. Any systematic center bias above the half-cell tolerance, silent ID switch, duplicate/absent false accept, or missing-frame drop disqualifies that raw proposal as the live observer. The existing SAM 2.1 tiny results fail the mapped half-cell center gate; SAM 3.1 has not yet been measured on this project's clips.

**Gate C — human reference reliability:** Apply the project's two-rater/three-development/five-held-out process above. If identity/visibility or center agreement fails, improve label instructions and repeat before looking at policy deltas.

**Gate D — generated-video observer freeze:** Compare the frozen proposal against blinded human labels on generated output, preserving per-frame error, coverage, visibility, identity, and confidence. Freeze all preprocessing and rejection rules before the confirmatory policy set. A single existing M0 convenience sample can reveal obvious disagreements; it cannot pass the multi-seed release gate.

**Gate E — policy evaluation:** Only after observer gates pass, score matched baseline/intervention cases using the policy plan. Keep framewise scoring, scene guards, background movement, and negative controls separate so improvement cannot arise from target disappearance, mask shrinkage, camera drift, or path-informed tracking.

## Main measurement risks to preserve in the record

- **Observer and treatment leakage:** A tracker initialized from the desired path, or a mask selected as the closest target to the requested waypoint, bakes the answer into measurement. Use only a frozen first-frame target prompt plus blinded human labels.
- **Center is not always shape invariant:** A mask centroid can move when an object rotates, deforms, or is partially occluded even if its 3D center follows the same path. A tight-box midpoint also shifts for non-symmetric silhouettes. Keep target class and center definition fixed; on the current sphere use tight-box midpoint as specified and retain exact projected center for synthetic calibration.
- **Tracker points are not object pose:** TAP and CoTracker follow the queried material point. Use multiple points as a consistency diagnostic, but do not average them and call the result object center without a rigid-object model and validation.
- **Synthetic-to-generated gap:** Exact Kubric labels validate transforms, scoring, and observer behavior on known render distributions. They do not validate SAM/TAP transfer to Wan textures, artifacts, motion, or compression. The generated samples still need independent human labels.
- **Camera motion aliasing:** Sparse landmarks can be absent, occluded, or low contrast; dense flow can be uncertain on plain backgrounds. Record landmark visibility and uncertainty. If the fixed-camera criterion fails, mark the case as a scene failure; do not stabilize it away for the primary path score.
- **Version/compute drift:** SAM 3.1 requires newer Python/CUDA than the local MPS environment and gated weight download. Pin the full repository commit, checkpoint identifier, dependency lock, input resolution, and prompt JSON for any comparison. Its published 848M-parameter figure and H100 multi-object speedup do not imply that a T4 run fits or is fast; profile with one short clip before expanding.
