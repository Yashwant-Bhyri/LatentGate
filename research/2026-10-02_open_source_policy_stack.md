# Open-source stack choices for causal 2D path correction

**Checked:** 2026-10-02  
**Scope:** short, fixed-camera video diffusion; one visible object; measure and correct its 2D center path.  
**Evidence status:** source and systems review only. No model was run for this memo.

## Recommendation

Keep **Wan2.1 T2V 1.3B + DiTraj** as the first backbone and open-loop path-control comparator. It matches the saved Wan sample, the current experiment design, and the available small NVIDIA-GPU lane. First establish whether a one-latent-cell trajectory-mask change after a shared denoising prefix can move the object in the commanded direction. Only if that actuation check passes should the team test the online loop: estimate the current path from a predicted-clean intermediate, apply a bounded residual to future path conditioning, and measure later-frame error against independent labels.

Treat **DiffTrack** as a second component, initially as a possible latent-space observer or temporal-consistency regularizer. Treat **Frame Guidance** as the principal alternate actuator if box-mask updates prove too weak: convert the requested path into framewise object masks or centers and minimize a differentiable predicted-frame loss during denoising. Both methods have concrete primary-paper support, but neither is a drop-in implementation of the proposed feedback controller for the exact Wan 1.3B stack.

Use **Tora** as an independent open-loop trajectory-conditioned baseline if its CogVideoX-based setup is useful after the first mechanism test. Use **Wan-Move** later, when a larger GPU and an image-conditioned protocol are acceptable. A plain **CogVideoX-2B** run is a reasonable separate two-billion-parameter smoke test, but it will not test the same Wan/DiTraj intervention without an architecture port.

This experiment establishes screen-space path adherence only. It cannot establish 3D pose, depth, contact, or physical validity.

### What these methods imply for policy design

The practical design space separates into three parts:

1. **Conditioning/actuation:** DiTraj changes where object tokens receive foreground conditioning; Tora and Wan-Move learn motion-conditioning representations; Frame Guidance pushes a loss gradient into latents; DiffTrack CAG changes cross-frame attention to strengthen correspondence.
2. **State/readout:** a video observer (human labels, SAM2/tracker) reads decoded intermediate frames; DiffTrack reads internal Q/K correspondences; DreamTraj is evidence that a small reader can decode motion from internal latent features.
3. **Policy:** a controller maps observed deviation and confidence to bounded future-path edits. None of the reviewed releases is this complete closed-loop policy for Wan 1.3B. The project’s proposed residual controller is therefore a distinct research contribution, not a claimed implementation already contained in DiTraj.

For the first gate, keep the control update discrete and interpretable: compare unchanged future boxes with `+1` and `−1` horizontal latent-grid-cell shifts after the same five-step noise prefix. Score the actual generated object center independently. If the sign is wrong, response is absent, or identity/visibility/background suffers, do not tune a live controller on top of it. If that passes, compare (a) open loop, (b) decode/observe no-op, (c) matched fixed shift, (d) correctly signed live residual, and (e) shuffled and sign-reversed residuals. A no-op arm must remain frame-identical if the observer/decode is intended to be observational only.

Frame Guidance can then be tested as a deliberately different actuator: make a target mask for each sampled frame from the box path, apply masked image-space/latent guidance at selected keyframes, and report its extra decode/backprop cost and background/appearance side effects. Do not compare it to the DiTraj path result without matched prompts, start state, seeds, and evaluation labels.

## Model and tool licensing

License terms differ by layer; the base model’s license does not override the method/repository license.

- **Wan2.1:** official code and models are Apache-2.0. [Official license statement](https://github.com/Wan-Video/Wan2.1#license-agreement).
- **DiTraj:** implementation is CC BY-NC 4.0, stated as research-only/no commercial use. This is the binding restriction for using its code in this research stack. [License statement](https://github.com/xduzhangjiayu/DiTraj#license).
- **Tora:** repository code is Apache-2.0, but its README says the released Tora weights require following CogVideoX’s license and calls the released CogVideoX-5B Tora weights academic research only. Review the checkpoint’s specific terms rather than assuming Apache applies to the weights. [Repo](https://github.com/alibaba/Tora).
- **Wan-Move:** its official repository states Apache-2.0 for code and model weights. [License statement](https://github.com/ali-vilab/Wan-Move#license-agreement).
- **CogVideoX-2B:** model card states Apache-2.0, including its Transformer and VAE modules. [Model license](https://huggingface.co/zai-org/CogVideoX-2b#model-license).
- **Frame Guidance and DiffTrack:** papers and code are public, but a top-level license was not visible in the reviewed repositories. Treat code reuse as unresolved until the exact checked-out revision/license is verified.
- **DreamTraj:** the paper is public; its reproducible code/release terms were not located in the primary links reviewed.

## Cloud and runtime fit

The current project machine has PyTorch MPS but no CUDA, and the local environment lacks Diffusers. That is adequate for annotation, notebook/code inspection, CPU scoring, and tiny synthetic fixtures; it is not the execution target for the CUDA-specific DiTraj pipeline. The saved 17-frame Wan sample was generated earlier on a cloud T4. The Kaggle draft inspected in the active task is not yet ready to run: it has setup/preflight cells but no completed inference cells, and its GPU session is off. Stage and review the exact notebook first, then inspect the live accelerator and quota before spending runtime.

For a short Wan/DiTraj pilot, prefer one **T4** and a deliberately short jointly-denoised clip: 17 RGB frames at 832×480, 30 steps for the current pilot definition, one seed for smoke/mechanism, then paired seed blocks only after the gates pass. DiTraj’s own published run is 81 frames / 50 steps on A100; it does not demonstrate T4 fit or throughput. The source’s dense mask allocation grows with the square of latent token count, so the short frame count reduces a real risk, but does not prove the run fits. Record peak GPU memory, host RAM, wall time, exact versions, and any CPU-offload settings during the smoke.

**Colab:** current official FAQ confirms eligible paid Google AI plans provide a monthly Colab compute-unit allotment and premium hardware access, but exact benefits depend on region/plan and GPU type/availability is dynamic. Confirm the signed-in account under Colab Settings → Subscription and query actual remaining units; the earlier account inspection for this project showed 0 units and a free-T4 usage-limit denial, so recheck before planning a Colab generation. [Official FAQ](https://research.google.com/colaboratory/faq.html).

**Kaggle:** its official notebook docs describe free GPU access, queues, and available P100/T4 configurations, with weekly quota monitoring in notebook/account settings. An attached T4 session must be confirmed live; notebook metadata or a saved draft does not reserve a GPU. [Notebook docs](https://www.kaggle.com/docs/notebooks), [GPU usage guidance](https://www.kaggle.com/docs/efficient-gpu-usage).

If a T4 run is unavailable, do not assume Google AI Pro means a specific GPU or a fixed number of samples. Confirm actual Colab units/GPU first. No training is required for the initial inference-time policy, so the immediate spend is accelerator runtime and model download/storage, not fine-tuning. A defensible dollar estimate requires the live provider, GPU, and per-hour price; the paper’s A100 timing cannot price a T4 run.

## Cost and evidence boundaries

- The immediate mechanism screen is three short samples with a common prefix: unshifted, one-cell left, one-cell right. It is a direction/actuation test, not an efficacy benchmark.
- A feedback smoke adds a decode-matched no-op and online residual arm. The additional VAE decode is a likely memory/time risk; the existing Wan M0 final-generation peak does not measure an in-loop intermediate decode.
- Do not generate independent still images to assess temporal path control. The diffusion model must denoise the short video jointly; export and inspect individual frames or frame chunks from that same clip.
- The first outcome must use a reliable per-frame object center and missing-object penalty, with visibility/identity, apparent extent, and fixed-background motion as guardrails. Automated masks/tracks are observers to validate against blinded human labels, not ground truth.
- No evidence in this memo says the feedback policy has run or improves trajectory error. A benefit claim needs held-out seed blocks, matched controls, independent labels, and a paired analysis at the clip/seed level.
