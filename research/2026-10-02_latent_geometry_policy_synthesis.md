# Latent geometry policy synthesis

**Updated:** 2026-10-02  
**Status:** research decision updated; no new diffusion generation or policy intervention run.  
**Purpose:** reconcile the geometry-first project target with the staged DiTraj trajectory pilot and choose a practical native-latent research path.

## Decision

The immediate research target is now **2D path adherence for one moving object under a fixed camera**. The longer-term project target remains rigid-object geometry consistency and manipulation. Projected shape/scale, identity, visibility, and background stability are guardrails for the first path experiment; this remains an image-space controllability test and does not establish metric 3D scale, orientation, contact, or physical correctness.

The strongest first published **path-control baseline** is **DiTraj**, which accepts per-frame bounding boxes and has a Wan2.1 path. It is a training-free open-loop control and the checked repository is CC BY-NC 4.0. The eventual LatentGate contribution must add feedback from the current generated state and beat full DiTraj on held-out paths/seeds; reproducing DiTraj alone is not the project's policy contribution.

**VGGRPO remains an adjacent latent-policy reference**, specifically for distilling a teacher into a differentiable latent observer and steering via a reward gradient. Its published reward is a poor direct fit for this first task: it smooths camera motion and protects static-scene reprojection consistency, filtering dynamic regions rather than following a manipulated object's path. Geometry Forcing remains relevant to intermediate geometry representations, but neither replaces the path-control baseline for this first box.

## What the primary sources establish

### VGGRPO: closest policy template, with an object-reward gap

VGGRPO connects video-VAE latents to a geometry foundation model through a learned 3D-convolutional stitching layer, distills the geometry model into an LGM, and computes geometry rewards directly from latent states. Its training experiments use Wan2.1-1B and Wan2.2-5B, LoRA rank 32, and a group size of 64. The LGM is trained for 20 epochs on videos generated by the base model plus DL3DV, RealEstate10K, and MiraData. Its full post-training cost is approximately **1,536 GPU hours**, so reproducing the full GRPO pipeline is outside the current free-T4 budget. [Paper, v2](https://arxiv.org/html/2603.26599v2)

The paper also gives a training-free inference alternative: predict geometry from the current latent, differentiate a geometry reward with respect to that latent, and modify the predicted velocity; their pseudocode applies this sparsely (default interval 20). This is the feasible branch to prototype after a compatible geometry observer exists. The paper's batch-4 reward-computation table reports 68.57 GB peak GPU memory for its latent reward implementation, so that result is not evidence of T4 fit; a short, downscaled single-sample smoke would still need an actual measured preflight. [Appendix B.2 and efficiency study](https://arxiv.org/html/2603.26599v2#appendix.B)

The key mismatch is the reward. VGGRPO's dynamic-scene geometry reward uses Any4D scene flow to filter dynamic regions and aggregate **static** structure; it primarily rewards camera smoothness and static-scene reprojection consistency. That is useful for protecting the table/background, but it can ignore or even suppress the manipulated object whose geometry we want to preserve. A LatentGate adaptation needs an **object-conditioned rigidity/shape/scale term**, with an independent object mask and a separate motion/trajectory guardrail. The paper's results are author-reported benchmarks, not evidence for object orientation or robotic contact.

As of this review, the official project page links the paper and a social post but does not expose an implementation or pretrained LGM checkpoint; the arXiv page also has no paper-linked official code repository. Treat code/checkpoint availability as **not located**, not as proof that the authors will never release it. The Any4D checkpoint itself is publicly linked by the official repository, but its 7.73 GB file and unspecified checkpoint terms require a separate compute/license audit before use. [VGGRPO project page](https://zhaochongan.github.io/projects/VGGRPO/) · [Any4D official repository](https://github.com/Any-4D/Any4D) · [Any4D checkpoint card](https://huggingface.co/airlabshare/any4d-checkpoint)

### Geometry Forcing: evidence for the representation hypothesis

Geometry Forcing aligns selected intermediate video-diffusion features with VGGT features using angular and scale-alignment losses. Its main controlled experiments use DFoT and Next-Frame Diffusion; the paper also reports a Wan2.1-1.3B text-to-video extension trained on 2K SpatialVID videos, but that appendix reports only modest aesthetic, image-quality, and motion-smoothness changes—not object geometry or trajectory metrics. The official repository's released code/checkpoint is centered on the paper's main DFoT path; a Wan checkpoint or drop-in Wan port was not located. This supports the hypothesis that geometry can become more legible at selected internal layers and warns against naïve feature MSE, but it does not establish a Wan object-geometry gain. It is training-time backbone alignment, not an inference-time state-feedback controller; retain it as the representation/probe reference rather than the immediate runtime intervention. [Paper, Appendix D.5](https://arxiv.org/html/2507.07982#D5) · [Official code](https://github.com/CIntellifusion/GeometryForcing)

### DiTraj: a useful, bounded image-plane control

DiTraj accepts per-frame bounding-box paths and modifies foreground/background attention plus early spatial RoPE in Wan2.1/CogVideoX. It is training-free, open-loop control and the checked repository is marked CC BY-NC 4.0. It is an appropriate path-control baseline for the staged 17-frame test, but does not estimate current object geometry and should not be described as 3D or physics control. [Paper](https://arxiv.org/html/2509.21839v2) · [Official code and license](https://github.com/xduzhangjiayu/DiTraj)

## Current evidence and instrumentation limit

The M0 run establishes a reproducible Wan2.1-T2V-1.3B generation baseline on a Colab T4. The saved red-ball frames show a proxy-mask area CV of 7.21% and a first-to-last thresholded area increase of 25.96%, but this single color-threshold measurement may reflect lighting, hue, or segmentation error. It is a screening lead only. A sphere cannot test orientation; a later geometry benchmark needs an asymmetric CAD object with known pose, masks, depth, and camera parameters (for example, a rendered mug or box).

I inspected the saved hidden-state artifact. `transformer_summaries.pt` stores `spatial_mean` and `spatial_std` with shape `[1, 5, 1536]` per selected block/step; it has already pooled away the 2D token grid. Those summaries cannot localize the ball or train an object-scale/pose probe. The next microscope capture must preserve spatial structure (for example, object-mask-pooled features plus a low-resolution spatial feature map at selected blocks and denoising steps) and include predicted-clean latent snapshots. Do not claim latent object observability from the current pooled summaries.

The local paired-path DiTraj notebook has passed local static checks only. A fresh read-only check of the private [Kaggle draft](https://www.kaggle.com/code/bvyashwantkumar/ditraj-wan-1-3b-pilot-research/edit) found Draft saved, session off, T4×2 selected, and only setup, blank, and duplicate T4-preflight cells. The prepared runner/smoke/results flow has not been staged there. No DiTraj inference, geometry-model inference, latent reward gradient, or improvement delta exists yet.

## First falsifiable LatentGate experiment

### Hypothesis

For the fixed-camera red-ball fixture, an object-state estimate from a selected predicted-clean video state can reduce **2D center-path error** beyond open-loop DiTraj. The policy must use signed current path residual and observer confidence to change the next denoising control update. Visibility, identity, apparent extent, and background stability are guardrails. Scale/shape consistency remains a later geometry branch.

### Small, ordered experiment

1. Finish blinded object-center/box/visibility/identity labels and the 17-frame base / SG / full-DiTraj comparison. Verify the repeated-token mask is active. Use the red threshold only as a secondary score.
2. Use same-start mirrored target paths and a direction-neutral prompt for the causal path test. Existing one-way direction-language runs remain runtime-smoke evidence only.
3. If the path smoke is scoreable, test whether the decoded predicted-clean state estimates independently labeled object center and confidence at held-out seeds. Current M0 pooled hidden summaries cannot localize position; the separate saved x0 screen is a red-threshold feasibility lead only. A state observer that cannot beat a constant/prompt-only predictor stops the gate branch.
4. Prototype bounded signed-residual feedback into the next denoising step's foreground cross-attention bbox mask. Keep DiTraj's early hard RoPE geometry fixed. Compare fixed open-loop DiTraj, one-read step-4 feedback, a decode-matched no-op, shuffled residuals, and sign-reversed residuals; keep any adaptive fractional-RoPE and mask-rasterization changes as separately versioned variants. The exact source-based insertion map is in [`ditraj_feedback_adapter_design_v1.md`](ditraj_feedback_adapter_design_v1.md).
5. Evaluate held-out seeds and at least one piecewise stop/turn path after mirrored horizontal motion passes. Primary metric: manual center ADE/FDE with missing-frame penalty and paired signed endpoint response. Guardrails: box/mask extent, visibility, identity, background stability, and blinded quality. An asymmetric prop and simulator ground truth are later requirements for orientation/pose claims.

### Predeclared signal and falsifiers

Treat a one-seed result as feasibility evidence only. A candidate pilot signal is a paired reduction of at least 20% in missing-frame-penalized normalized center-path error versus full DiTraj, correct signed response for both mirrored paths, at least 90% object visibility, and no material degradation in identity, apparent extent, background stability, or blinded quality. Falsify the learned gate if a compute-matched fixed schedule matches it, if shuffled/zeroed state inputs retain the gain, if observer confidence is uncalibrated, or if the apparent improvement comes from object disappearance, duplication, hue manipulation, or background/camera changes. Do not expand to LoRA/GRPO until a small held-out test supports the inference-time gate.

## Decision for the next cycle

- Use **DiTraj** as the path-control baseline; adapt it only after the direction-reversal and independent evaluator tests pass.
- Keep **VGGRPO** as a possible latent-reward-gradient implementation reference; its full group-RL pipeline (about 1,536 GPU hours) is not the first experiment.
- Keep **Geometry Forcing** as a geometry representation/probe reference for the later 3D/shape consistency phase.
- Do not let a 2D path score stand in for rigid-object geometry, contact, or physics.
- Before any gate implementation, resolve object mask quality, teacher-to-latent calibration, and T4 memory/runtime with one bounded inference smoke. If the T4 cannot hold a usable differentiable observer, reduce resolution/frames or run teacher-side processing separately; never imply fit from parameter count alone.
- Continue the literature audit on object-centric rewards, dynamic 4D reconstruction, differentiable feature/shape metrics, and latent policy guidance. The novel contribution is not established until that collision audit and the controlled experiment are complete.
